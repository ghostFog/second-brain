# 设计与功能需求（变更前必查）

> **权威正文已迁至** **`doc/`**，本文件仅作重定向，不承载详情，避免两处脱节。

**核心规则：实现或修改任何功能前，必须先读以下文档 + 设计稿，再编码。**

## 必读文档

1. **视觉权威**：`doc/设计文档.md`（设计体系、各页布局与元素）。
2. **功能权威**：`doc/功能需求文档.md`（按页面枚举全部功能点，**不要遗漏**）。
3. **原始设计稿**：`design/pages/*.html`，共 5 页：
   `主编辑器.html`、`命令面板.html`、`图谱视图.html`、`插件市场.html`、`设置.html`。
4. **视觉规范（Design Token）**：`second-brain/css/base.css`。

## 变更前标准动作

1. 先读 `doc/功能需求文档.md` + `doc/设计文档.md` + 对应设计稿，明确视觉与交互目标、扫描是否有遗漏功能点。
2. 涉及文件变更：先展示改动前后对比，确认后再写入。
3. 实现后只测本次改动。
4. 改动如影响文档内容，同步更新 `doc/` 及 AGENTS.md 导航。

## 附录：设计文档 / 功能需求文档 编写示例

> 两份文档在 `doc/` 均有权威正文，本附录仅说明**推荐的三档结构与书写口径**，供编写/补充时参考，正文始终以 `doc/` 为准。

### 一、功能需求文档（doc/功能需求文档.md）

按「页面」分组，每页一张表；表格列固定为 `编号 | 功能点 | 说明 | 交互/数据`；只陈述「做什么」，不写「长什么样」。

示例（真实格式）：

| 编号    | 功能点     | 说明                     | 交互 / 数据                            |
| ----- | ------- | ---------------------- | ---------------------------------- |
| ED-09 | 编辑/预览模式 | 行尾 `pencil` / `eye` 切换 | 点击切换模式                             |
| G-10  | 迁移默认知识库 | 把默认库内容迁移到用户选择的新目录      | 移动语义：选目录→二次确认→复制→清空原库→新目录成为默认库并持久化 |

书写口径：

- **编号**用「页面前缀」+ 递增序号（`G-` 全局框架 / `ED-` 主编辑器 / `AI-` / `ST-` 设置…），唯一不重复。

- **一行一个功能点**，无副表拆字段；快捷键、多步交互写进「交互/数据」列。

### 二、设计文档（doc/设计文档.md）

与需求文档一一对应，回答「长什么样 / 怎么交互」。建议三档结构：

```
0. 设计令牌与通用组件   （色彩/字体/圆角/组件，全局唯一）
1. 全局框架             （标题栏 / Ribbon / 右键菜单，所有页面共享）
2. 主编辑器             （三栏：文件树 / 编辑器区 / 右侧面板）
3+ 其余页面             （命令面板 / 图谱 / 插件 / 设置 / AI）
```

示例（真实章节名）：

- **`### 2.2 中间编辑器`** 下的子条目，先写「标签栏（高 36px）」再分点列按钮（`pencil` / `eye` / `columns`…）与交互，末尾「状态栏」等。

- **`### 1.1 标题栏`**：按「左侧 / 中间 / 右侧」分段描述，含尺寸、图标名、快捷键、浮层行为，并引用需求编号（如 G-07）。

书写口径：

- 需求文档讲「做什么」，本文讲「长什么样/怎么交互」，两两对应不脱节。

- 涉及视觉时引用 Design Token 变量（如 `--note-*`），不硬编码色值。

#### 格式示例：以「2.2 中间编辑器」为例

标题层级用 `##`（页面）/ `###`（分区）/ `####`（关键交互）；正文用「项目符号 + 加粗条目」分段，末尾用 `（ED-xx）` 反向引用需求编号：

```markdown
### 2.2 中间编辑器（弹性伸缩）

- **标签栏（高 36px）**：每文件一 Tab，可横向滚动；行尾 `pencil`（切换源码/所见即所得）、`eye`（仅预览）、`columns`（分屏，可再次点击关闭）切换视图；`more-horizontal` 更多菜单（占位）。

- **查找 / 替换条**：`Ctrl+F` 打开查找条、`Ctrl+R` 打开替换条（编辑器顶部工具条）：查找输入即时计数（当前/总数）、上一下一按钮跳转并高亮选中匹配；替换支持「替换当前」「全部替换」；`Esc` 关闭（ED-33 / ED-34）。

- **正文区**：
  - Markdown 渲染：H1/H2、段落、列表、待办、行内代码 / 加粗 / 链接；
  - 代码块：`terminal` + 语言标 + 复制按钮 + 语法染色。

- **状态栏**：已自动保存 + Markdown + UTF-8 + 行/列 + 字数 + 中文，随编辑变化。
```

格式要点：

- **分区标题**要含尺寸或定位，如「中间编辑器（弹性伸缩）」「标题栏（高 36px）」。

- **交互细节**（快捷键、多步行为、联动持久化）写进该条目的说明里，不另开表。

- 子项用**嵌套缩进 bullet** 表达同一组件的多状态/多子件。

- 每条尽量以需求编号结尾（`ED-32` / `G-07`），保持与需求文档双向追踪。
