## 8. 数据层（笔记存储与 IPC）

> 全模块公共底座：编辑器 / 图谱 / 插件 / 设置的持久化统一走本层；桌面端用 Electron 真实文件系统，网页版降级为内存 mock。

### 8.1 笔记库位置与 seed

- **根目录**：`app.getPath('userData')/vault`（Electron 标准用户数据目录，不透传用户笔记到源码 / 打包产物）。

- **首次启动**：若 vault 为空，用内置 seed（把编辑器 / 图谱示例内容转成真实 `日记/2024年/09月/09-01.md` 等）写入，使图谱 / 编辑器开箱即有数据。

### 8.2 IPC 协议（主进程 `main.js`）

一组 `ipcMain.handle`，全部以**相对路径**为 key（拼接到 vault 后校验前缀，防路径穿越）：

| 通道 | 说明 |
| --- | --- |
| `notes:list` | 递归扫描 vault 内 `*.md`，返回 `[{path, name, folder, mtime, size}]` |
| `notes:read(path)` | 返回文件内容字符串 |
| `notes:save(path, content)` | 写文件（自动建父目录） |
| `notes:create(name)` | 在选定目录新建空 `.md`，返回完整相对路径 |
| `notes:delete(path)` | 删除文件（可回收则移入 trash） |

### 8.3 渲染层桥（`preload.js` → `js/app-*.js`）

- `preload.js` 在 `noteDesktop` 上暴露 `listNotes / readNote / saveNote / createNote / deleteNote`（内部 `ipcRenderer.invoke`），保留现有窗口控制。

- `js/app-note.js` 内 `noteStore` 模块（IIFE 内函数）：优先用 `window.noteDesktop`；网页版无桥时降级为**内存 mock**（内置示例库），保证 `start-server.bat` 调试仍可用；统一暴露 `list / read / save / create / remove` 供各视图调用。

## 附录 · 闭环改造背景与说明

> 由 `完善第二脑为可用编辑器闭环.md` 并入本文档（2026-09-04）。设计要点已归位至对应章节，此处保留不归属任何单一视图的背景 / 推进 / 验收说明。

### 背景

第二脑此前为高保真演示版：正文不可编辑、文件树 / 状态栏 / 元信息为硬编码、图谱 / 插件 / 设置多处占位。目标为做成「可用编辑器闭环」：桌面端真实读写磁盘 `.md`，各视图交互补成真实逻辑；持久化采用 Electron 真实文件系统，网页版保留降级可用。

### 推进顺序

因编辑器与数据层是所有模块公共底座，依次推进：**数据层 + 编辑器闭环 → 图谱 → 插件市场 → 设置**，分块提交、逐块验收。

### 验收方法

- **桌面版（主形态）**：`cd second-brain; npm start`，实际新建 / 编辑 / 保存一条笔记 → 到 `userData/vault` 确认 `.md` 落盘 → 重启应用数据保留。
- **网页版降级**：`start-server.bat` → `http://127.0.0.1:8000/index.html` 仍可用（内存数据）。
- 浏览器实测关键交互 + 控制台无报错。

### 文档同步

每块完成后推进 `../开发进度.md` 对应行状态并补记录；涉及的功能点同步在 `../功能需求文档.md` 登记 / 标注。
