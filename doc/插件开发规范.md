# 第二脑 · 插件开发规范

> 本文档定义第二脑插件体系的接口规范、manifest 字段说明、扩展点（Ribbon 图标、命令面板、右键菜单）的注册方式，以及插件 action 实现约定。
> 阅读对象：插件开发者、第二脑维护者。

***

## 1. 设计目标

| 目标               | 说明                                                        |
| ---------------- | --------------------------------------------------------- |
| **最小侵入**         | 插件只需在 manifest 里声明扩展点，无需修改宿主代码                            |
| **声明式 manifest** | JSON 数据不含函数，action 通过 actionKey 在 JS 层映射成实际回调             |
| **三个扩展点**        | Ribbon 图标（PL-10）、命令面板（PL-12）、右键菜单（PL-11）                  |
| **目录化插件**        | 插件是独立目录 `plugins/<id>/`（manifest.json + main.js），启动自动扫描加载 |
| **向后兼容**         | 未声明任何扩展点的旧插件（仅 name/icon/desc/downloads/rating）继续可用       |

***

## 2. 插件 Manifest 规范

每个插件在插件市场数据中是一条 JSON 对象，字段分三层：**基础信息、扩展点声明、运行时元数据**。

### 2.1 基础信息（必填）

| 字段          | 类型     | 说明                                                              |
| ----------- | ------ | --------------------------------------------------------------- |
| `name`      | string | 插件显示名称，如 `"Git Sync"`                                           |
| `id`        | string | 插件唯一标识（推荐小写+连字符，如 `"git-sync"`）。若省略则由 name 自动生成                 |
| `author`    | string | 作者名                                                             |
| `icon`      | string | Lucide 图标名（详见 [Lucide Icons](https://lucide.dev)）               |
| `color`     | string | 图标块背景色（HEX），如 `"#22C55E"`                                       |
| `cat`       | string | 分类：`editor` / `theme` / `sync` / `productivity` / `integration` |
| `desc`      | string | 两行以内简短描述                                                        |
| `downloads` | number | 下载量（展示用）                                                        |
| `rating`    | number | 评分 1.0–5.0（展示用）                                                 |

### 2.2 扩展点声明（可选）

三个扩展点字段都是**可选的**——不声明就是不使用该扩展点。

#### 2.2.1 `ribbon` —— PL-10 左侧图标入口

```json
{
  "ribbon": {
    "icon": "highlighter",
    "title": "高亮（切换上次颜色）",
    "actionKey": "toggle"
  }
}
```

| 字段          | 类型       | 必填 | 说明                                                     |
| ----------- | -------- | -- | ------------------------------------------------------ |
| `icon`      | string   | 是  | 图标名，缺省回退到顶层 `icon`                                     |
| `title`     | string   | 是  | hover tooltip，缺省回退到顶层 `name`                           |
| `actionKey` | string   | 否  | **推荐**。声明性 action key，JS 层注入为 `onClick`（优先级高于 `route`） |
| `route`     | string   | 否  | 点击后跳转的 hash 路由，如 `"#/plugins"`；仅当未提供 `actionKey` 时生效   |
| `onClick`   | function | 否  | 自定义点击回调（仅在 JS 层 materialize 时设置，JSON 里不放）              |

**行为**：启动时自动在 Ribbon 的 `ribbon-spacer`（同步状态圆点）前插入按钮；点击执行 `onClick`（由 `actionKey` 映射），否则执行 route 跳转。**未提供 actionKey 也未提供 route 时点击无反应，因此至少二者其一必填。**

#### 2.2.2 `commands` —— PL-12 命令面板命令

```json
{
  "commands": [
    { "icon": "git-commit", "label": "提交当前变更", "actionKey": "git-commit" },
    { "icon": "git-pull",   "label": "拉取最新代码", "actionKey": "git-pull" },
    { "icon": "git-push",   "label": "推送到远程", "actionKey": "git-push", "shortcut": "⌘⇧P" }
  ]
}
```

| 字段          | 类型     | 必填 | 说明                                                                         |
| ----------- | ------ | -- | -------------------------------------------------------------------------- |
| `icon`      | string | 是  | Lucide 图标名                                                                 |
| `label`     | string | 是  | 命令名称，用户在命令面板看到的文字                                                          |
| `actionKey` | string | 是  | **声明性 action key**，JS 层通过 `PLUGIN_ACTION_MAP[pluginId][actionKey]` 映射为实际函数 |
| `shortcut`  | string | 否  | 快捷键提示（仅展示，不绑定真实按键，如 `"⌘⇧H"`）                                               |

**行为**：安装后命令面板 `Ctrl+P` 自动追加一个分组「插件名 插件」，命令按数组顺序显示，被搜索到的自然过滤。

#### 2.2.3 `contextMenus` —— PL-11 右键菜单注入

```json
{
  "contextMenus": {
    "file-tree": [
      { "label": "Git: 查看历史", "icon": "history", "actionKey": "git-history" }
    ],
    "file-tree-folder": [
      { "label": "Git: 对比差异", "icon": "git-compare", "actionKey": "git-diff" }
    ],
    "editor": [
      { "label": "Git: 还原此段落", "icon": "undo-2", "actionKey": "git-history" }
    ]
  }
}
```

**三个 slot 含义**：

| Slot               | 触发位置                           | 目标节点      |
| ------------------ | ------------------------------ | --------- |
| `file-tree`        | 编辑区左侧文件树的**笔记**节点右键            | 单个 .md 文件 |
| `file-tree-folder` | 编辑区左侧文件树的**目录**节点右键            | 文件夹       |
| `editor`           | 编辑区 textarea 内右键（仅当打开 .md 笔记时） | 当前文档/选区   |

菜单项字段：

| 字段          | 类型      | 必填 | 说明                 |
| ----------- | ------- | -- | ------------------ |
| `label`     | string  | 是  | 菜单项文字              |
| `icon`      | string  | 否  | Lucide 图标名         |
| `actionKey` | string  | 是  | 同 commands，映射到实际回调 |
| `disabled`  | boolean | 否  | 禁用态（灰显不可点）         |
| `children`  | array   | 否  | 二级子菜单（结构相同，支持嵌套）   |

**行为**：原宿主菜单末尾插入 `'-'` 分隔线后接插件菜单项；多个插件的菜单项按插件安装顺序依次追加。

### 2.3 运行时元数据

| 字段          | 类型      | 说明                                                                                          |
| ----------- | ------- | ------------------------------------------------------------------------------------------- |
| `installed` | boolean | 当前是否已安装。JSON 里可预设为 `true`；JS 层的 `toggleInstallPlugin` 会联动 `PluginManager.install/uninstall` |

## 3. actionKey → 回调映射（JS 层）

JSON 里不放函数引用（保持可序列化 + 可内嵌到 HTML `<script type="application/json">`），而是通过 `actionKey` 字符串在 JS 层映射。

### 3.1 PLUGIN\_ACTION\_MAP 结构

在 `app-plugins.js` 中定义：

```js
const PLUGIN_ACTION_MAP = {
  'git-sync': {
    'git-commit': function () { /* 提交逻辑 */ },
    'git-pull':   function () { /* 拉取逻辑 */ },
    'git-push':   function () { /* 推送逻辑 */ },
    'git-history': function () { /* 历史逻辑 */ },
  },
  'encrypt': {
    'encrypt-file': function () { /* 加密逻辑 */ },
    'decrypt-file': function () { /* 解密逻辑 */ },
  },
};
```

### 3.2 materializePlugin 机制

```js
const fakePlugin = { id: 'git-sync', commands: [{ actionKey: 'git-commit', /* ... */ }] };
const materialized = materializePlugin(fakePlugin);
// materialized.commands[0].action 现在是 PLUGIN_ACTION_MAP['git-sync']['git-commit']
```

materializePlugin 做的事情：

1. 从 `PLUGIN_ACTION_MAP[pluginId]` 取出 action 映射表
2. 遍历 `commands` 数组：`c.actionKey → c.action`
3. 遍历 `contextMenus` 各 slot：`m.actionKey → m.action`
4. 返回注入完成的对象副本（不修改原对象）

## 4. PluginManager API

所有扩展点查询统一走 `pluginManager` 单例：

```js
// 查询已安装插件列表
pluginManager.list()                → [{id, name, ribbon, commands, contextMenus}, ...]

// PL-10: 获取所有 Ribbon 按钮
pluginManager.getRibbonItems()      → [{pluginId, icon, title, route, onClick}, ...]

// PL-12: 获取命令面板分组
pluginManager.getCommands()         → [{group: '插件名 插件', items: [{icon, label, action, shortcut}, ...]}, ...]

// PL-11: 获取指定 slot 的右键菜单项
pluginManager.getContextMenus(slot) → [{label, icon, action, disabled, children}, ...]
// slot ∈ { 'file-tree', 'file-tree-folder', 'editor' }

// 生命周期
pluginManager.install(plugin)       // 注册插件 + 刷新 Ribbon
pluginManager.uninstall(pluginId)   // 注销插件 + 刷新 Ribbon
pluginManager.clearAll()             // 清空（启动重建用）
```

## 5. 扩展点注入位置一览

| 扩展点       | 宿主文件                                           | 注入方式                                                                                            |
| --------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Ribbon 图标 | `index.html` `.ribbon` 容器                      | `pluginManager.refreshPluginRibbonButtons()` 在 `ribbon-spacer` 前插入 `button[data-plugin-ribbon]` |
| 命令面板      | `app-core.js` `buildCommandList()`             | 追加 `pluginManager.getCommands()` 到 groups                                                       |
| 文件树右键菜单   | `file-tree-ctx.js` `showFileTreeContextMenu()` | 追加 `pluginManager.getContextMenus(isFolder? 'file-tree-folder':'file-tree')`                    |
| 编辑区右键菜单   | `app-editor-ctx.js` `buildEdCtxSchema()`       | 追加 `pluginManager.getContextMenus('editor')`                                                    |

## 6. 插件目录机制（推荐）

正式插件应放在独立目录中，由应用启动时自动扫描加载，无需修改宿主代码。

### 6.1 目录结构

```
plugins/
└── <plugin-id>/            # 目录名与 manifest.id 一致
    ├── manifest.json       # 插件元数据 + 扩展点声明（见第 2 节，不含 installed）
    └── main.js             # 插件实现：调用 PluginAPI.register(id, actions) 注册回调
```

* 插件根目录：`second-brain/plugins/`（应用根目录下）

* **目录存在即视为已安装**；manifest 缺失/损坏或缺少 `id` 的目录会被跳过

* 同一 `id` 与内置插件冲突时，**目录插件优先**（覆盖内置声明）

### 6.2 加载链路

```
启动 → initPluginSystem() ──→ 内置 DEFAULT_PLUGIN_DATA 注册
                        └──→ loadDirPlugins()（异步）
                               ├─ 1. 主进程 scanPlugins() 扫描 plugins/ 读各 manifest.json（IPC plugins:list）
                               ├─ 2. 渲染进程 fetch('plugins/<id>/main.js') → 注入沙箱执行
                               ├─ 3. main.js 里 PluginAPI.register(id, actions) 注册 actionKey 回调
                               ├─ 4. materializePlugin 合成完整插件（actionKey → 函数）
                               └─ 5. 合并进 pluginData + pluginManager.install()
```

* **主进程**（[main.js](file:///d:/project/aiCode/second-brain/second-brain/main.js)）：`scanPlugins()` 扫描目录、`plugins:list` / `plugins:reveal` 两个 IPC

* **preload**（[preload.js](file:///d:/project/aiCode/second-brain/second-brain/preload.js)）：暴露 `noteDesktop.plugins.list()` / `noteDesktop.plugins.reveal()`

* **渲染进程**（[app-plugins.js](file:///d:/project/aiCode/second-brain/second-brain/js/app-plugins.js)）：`loadDirPlugins()` + 全局 `PluginAPI`

* **网页版降级**：无 `noteDesktop.plugins` 时目录加载自动跳过，仅用内置插件

### 6.3 main.js 与 PluginAPI

main.js 以 IIFE 形式接收 `(PluginAPI, pluginId)` 两个参数，把 actionKey 回调注册进全局映射表：

```js
/* 插件主实现 — 由宿主注入沙箱执行 */
(function (PluginAPI, pluginId) {
  'use strict';

  /* ...插件自己的辅助函数... */

  /* 向宿主注册全部 actionKey 回调 */
  PluginAPI.register(pluginId, {
    'yellow': function () { /* 用黄色高亮 */ },
    'clear':  function () { /* 清除高亮 */ },
  });
})(PluginAPI, pluginId);
```

| API                               | 说明                                                                         |
| --------------------------------- | -------------------------------------------------------------------------- |
| `PluginAPI.register(id, actions)` | 把 `{ actionKey: fn }` 合并进全局 `PLUGIN_ACTION_MAP[id]`，`id` 须与 manifest.id 一致 |

**main.js 里可以直接使用宿主的全局 API**：`document`、`localStorage`、`showToast()`、`alert()`、`prompt()`、`confirm()` 等。

### 6.4 打开插件目录

桌面版中通过 IPC `plugins:reveal` 可在系统文件管理器中打开插件目录，方便查看/放置插件。

## 7. 编写新插件的步骤

> 推荐按目录化方式开发（第 6 节）。目录化插件可独立分发、不修改宿主代码；内置方式（写死进 app-plugins.js）仅用于官方内置示例。

假设你要写一个「内容高亮」插件，目录化步骤如下：

### Step 1 — 创建目录与 manifest

`plugins/highlight/manifest.json`：

```json
{
  "id": "highlight",
  "name": "内容高亮",
  "author": "第二脑官方",
  "icon": "highlighter",
  "color": "#F59E0B",
  "cat": "editor",
  "desc": "对 Markdown 文本进行多颜色高亮，支持黄/绿/红/蓝四种颜色。",
  "downloads": 0,
  "rating": 5.0,
  "version": "1.0.0",
  "main": "main.js",
  "ribbon": { "icon": "highlighter", "title": "高亮（切换上次颜色）", "actionKey": "toggle" },
  "commands": [
    { "icon": "highlighter", "label": "高亮: 黄色", "actionKey": "yellow" },
    { "icon": "palette", "label": "高亮: 选择颜色", "actionKey": "pick-color" },
    { "icon": "eraser", "label": "清除高亮", "actionKey": "clear" }
  ],
  "contextMenus": {
    "editor": [
      { "label": "高亮: 黄色", "icon": "highlighter", "actionKey": "yellow" },
      { "label": "清除高亮", "icon": "eraser", "actionKey": "clear" }
    ]
  }
}
```

> manifest 里**不要写** `installed`（由目录存在与否决定），也不要放函数（保持可序列化）。

### Step 2 — 编写 main.js 注册回调

`plugins/highlight/main.js`（见 6.3）：实现各 actionKey 逻辑后统一 `PluginAPI.register(pluginId, {...})`。

### Step 3 — 验证加载

1. 重启应用（或重新进入插件页）→ 目录插件自动扫描加载
2. 左侧 Ribbon 出现 highlighter 图标（ribbon.actionKey 生效）
3. `Ctrl+P` → 搜「高亮」看到「内容高亮 插件」分组
4. 编辑区右键 → 看到高亮菜单
5. 点击/执行回调 → 触发真实逻辑

### 内置方式（不推荐，仅官方示例）

若需内置（如 Calendar / Minimal Theme 官方演示），仍走旧流程：在 `app-plugins.js` 的 `PLUGIN_ACTION_MAP` 注册回调、在 `DEFAULT_PLUGIN_DATA` 添加 manifest 并把 `installed` 设为 `true`。

## 8. 扩展约定

| 约定                    | 说明                                                       |
| --------------------- | -------------------------------------------------------- |
| **无扩展点零侵入**           | 插件只填基础信息，不声明 ribbon/commands/contextMenus 时，不修改宿主任何 DOM  |
| **actionKey 必须有对应回调** | 缺失时 materializePlugin 会降级为 `alert('插件命令未实现: x')`         |
| **禁用态**               | contextMenus 支持 `disabled: true`，菜单项会灰显但仍渲染              |
| **子菜单嵌套**             | contextMenus 项支持 `children: []`，最多两层（与宿主现有右键菜单一致）        |
| **生命周期**              | `pluginManager.install()` 后自动刷新 Ribbon；`uninstall()` 后清理 |
| **目录优先**              | 目录插件与内置插件 `id` 冲突时，目录插件覆盖内置                              |
