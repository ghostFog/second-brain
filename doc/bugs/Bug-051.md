# Bug-051 · 编辑区内点击相对链接触发 404 弹窗——相对链接按 note:// 基址解析到应用目录而非笔记目录。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-051
- **日期**: 2026-09-13
- **现象**: 在编辑区（IR/WYSIWYG/预览）点击指向其他笔记的相对链接（如 `[新笔记](新笔记-13-838.md)` 或 `[子笔记](sub/child.md)`）时，弹出 404 错误页「Not Found: D:\project\aiCode\second-brain\second-brain\新笔记-13-838.md」。`[[wiki]]` 链接同样受影响。外链（http/https）正常打开。
- **复现地点**: `js/editor/editor-host.js`（原链接点击委托块，已迁出）+ `main.js`（`note://` 协议 handler 基址映射）
- **原因**: 应用通过 `note://local/index.html` 加载，`note://` 协议 handler 将路径映射到**应用根目录 ROOT**。编辑区内 `<a href="新笔记-13-838.md">` 的相对链接未在点击时拦截判断，浏览器按当前文档基地址 `note://local/` 解析为 `note://local/新笔记-13-838.md` → handler 在应用根目录找该文件 → 不存在 → 404。根因有二：
  1. 宿主 `editor-host.js` 的链接点击委托块用 `findNoteByLink` 判断目标是否库内笔记，但该逻辑混在宿主主体中，不符合「链接导航是 markdown-editor 插件能力」的架构原则；
  2. 主进程 `createWindow` 未对 `will-navigate`/`setWindowOpenHandler` 做安全兜底，未命中导航直接放行给 `note://` handler 触发 404 弹窗。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. **链接导航逻辑迁至插件** `plugins/markdown-editor/md-linknav.js`：document 捕获阶段委托，命中内部笔记 → `PluginAPI.editor.openNote(path)` 新开页签；外链放行；未命中但疑似 `.md` 链接 → `preventDefault` 避免 404。路径解析按**链接所在笔记的目录**计算相对路径（`./`、`../`、同目录、`sub/`、`/` 开头从库根）。宿主 `editor-host.js` 删除原委托块，仅保留 `PluginAPI.editor.openNote/listNotes` 桥接供插件调用。
  2. **主进程 `main.js` `createWindow` 加导航安全兜底**：`setWindowOpenHandler` deny + `will-navigate` preventDefault，防止任何未拦截的导航逃逸到 `note://` handler 触发 404 弹窗。
  3. **`manifest.json` scripts 数组加入 `md-linknav.js`** 确保插件加载时注册链接导航模块。
- **验证结果**:
  - `regression.test.js` 新增 `testLinkNavDelegate`（4 场景：内部命中 → openNote；外链 → 放行；未命中 .md → preventDefault 防 404；wiki 命中 → openNote），`npm test` 148 通过、0 失败。
  - 语法检查 `node -c` 对 `md-linknav.js`/`editor-host.js`/`main.js`/`app-plugins.js`/`editor-sidepanel.js`/`app-graph.js` 均通过。
- **防再犯要点**: 编辑区内链接点击的导航判断属于「markdown 编辑器插件能力」，不应混入宿主主体；宿主仅提供 `openNote`/`listNotes` 桥接。主进程必须对 `will-navigate`/`setWindowOpenHandler` 做 deny 兜底，避免任何未拦截的相对导航逃逸到自定义协议 handler 触发 404 弹窗（CD-38 新增）。
