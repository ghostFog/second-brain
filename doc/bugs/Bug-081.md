# Bug-081 · 偶发锁屏只显示深色遮罩、看不到密码输入框与卡片

| 字段   | 说明                                                                                  |
| ---- | ----------------------------------------------------------------------------------- |
| ID   | Bug-081                                                                             |
| 日期   | 2026-11-20                                                                          |
| 现象   | 应用锁屏偶发异常：`#lock-screen` 深色遮罩已铺满窗口（主视图已被隐藏），但遮罩内的 `.lock-card`、密码输入框、解锁按钮全部不可见，窗口呈「深色空白」，无法输入密码。偶发，非必现。 |
| 触发场景 | 经用户确认：**遮罩出现但卡片/密码框空白**。对应托盘召回 / 最小化恢复（`minimize`/`hide` 时先锁定、`show`/`restore` 时恢复显示）与启动首帧两条路径。 |
| 根因 1 | **隐藏期绘制未完成 + 恢复可见时未触发重绘（主因）**：窗口最小化/缩托盘瞬间主进程即推送 `app:locked`，渲染端在窗口已隐藏时把遮罩 `display` 置为 `flex`；恢复可见时 `app:locked` 与 `visibilitychange` 再次调用 `showLock()`，但只是把 `display` **重复赋成同一个值**，不产生样式失效，合成层停留在「只画了遮罩背景、卡片尚未绘制」的旧帧，且后续无任何重绘触发 → 一直空白。 |
| 根因 2 | **解锁记录键不一致（放大偶发概率）**：`app:unlock` / `app:getSecurity` 用 `event.sender.id`（webContents id）记录与查询解锁态，而 `secRequireLock` 却用 `win.id`（BrowserWindow id）删除。两个 id 空间相互独立（打开过开发者工具、日志浮窗等对象后会产生偏移），删除命中不到真实键 → 残留「该窗口已解锁」旧态；渲染端一旦走 `getState` 查询而不是推送事件，就会误判为已解锁而不弹密码框。 |
| 根因 3 | **DOM 就绪兜底缺失（防御项）**：同步启动锁与 `init()` 都只在 `DOMContentLoaded` 上执行；若脚本在文档已就绪后才执行（缓存/延迟加载），事件已错过 → `body.locked` 已隐藏主视图，遮罩却始终 `display:none`（同表现为深色空白），且解锁按钮无绑定。 |
| 处理方法 | 1）`js/app-security.js`：新增 `forceRepaint(screen)`（`display:none` → 读 `offsetHeight` 强制重排 → `display:flex`，同帧完成不闪烁）；`showLock()` 检测「已显示」时强制重绘，并新增 `ensureCardPainted()` 下一帧校验卡片宽高、异常最多重试 3 次；2）同步启动锁与 `init()` 按 `document.readyState` 判断——`loading` 才等 `DOMContentLoaded`，否则立即执行；3）`main.js`：`secRequireLock` 改为按 `win.webContents.id` 删除解锁记录，并新增 `reason`（show/restore/minimize/hide）日志、解锁成功/失败日志、超时锁定广播日志，便于后续复盘；4）新增回归断言 `testSecurityLockOverlay`（Bug-081-1~6）。 |
| 验证结果 | `npm test` 全量 **387 条通过 / 0 失败**（含本次新增 6 条）。渲染端日志 `[security-ui] showLock ...`、主进程日志 `[security] 锁定窗口 reason=...` 已落 `userData/logs/app.log`，可用于真机复现时核对时序。待真机复验偶发场景。 |
| 状态   | 已修复（测试完成）                                                                   |
| 防再犯要点 | **CD-61**：见 `doc/bugs/防再犯清单.md`。 |

## 定位过程

1. 用户描述「锁屏时没有显示密码输入框」，确认后明确为「遮罩在、卡片/密码框空白」。
2. 阅读 `js/app-security.js`、`main.js` 安全区块、`index.html` 锁屏结构、`css/app.css` 锁屏样式：
   - 遮罩背景是字面量 `rgba(0,0,0,0.55) + backdrop-filter`，一定绘制；
   - 卡片完全由静态 HTML + 常驻 CSS 构成，不存在「条件下隐藏卡片」的规则；
   - 排除层叠/覆盖（`#lock-screen` 为 `z-index:99999` 的 fixed 全屏层，无更高层覆盖）。
3. 找到两条可解释「背景在、卡片无」的路径：
   - 遮罩在窗口隐藏期间被置为显示，恢复可见时只重复赋同值 → 合成层不重绘；
   - `body.locked` 已在但 `showLock` 从未执行（DOMContentLoaded 已错过）→ 深色空白。
4. 同时发现 `secWinUnlocked` 的写入/查询键（webContents id）与删除键（BrowserWindow id）不一致，会残留解锁态。
5. 用 Electron 探针实测：`BrowserWindow.id` 与 `webContents.id` 在简单场景下碰巧相同，但属于两套独立自增计数器，存在偏移空间 → 支持「偶发」特征。
