# Bug-062 · Git 提交锁冲突 cannot lock ref 'HEAD' 与无远程误报 git 操作失败

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-062
- **日期**: 2026-09-20
- **现象**: ① 实时/手动提交时偶发 `fatal: cannot lock ref 'HEAD': Unable to create '.../refs/heads/master.lock': File exists. Another git process seems to be running.`（残留 `.lock` 或并发占锁）；② 知识库**未配置远程**时，每次探测都写一条「git 操作失败: git remote get-url origin」错误日志，噪音大。
- **复现地点**: `second-brain/main.js`（`gitRun` 校验后直接 `execFile` 执行）
- **原因**: ① 同一知识库的 git 命令未串行：实时提交（git-sync 文件树变更触发 `commitNow`）与手动提交/推送可并发执行；且上次 git 进程异常退出会遗留 `.git/refs/.../*.lock`，git 视为仍有进程占锁而拒绝操作。② `git:check` 用 `git remote get-url origin` 探测远程，无 origin 时 git 非零退出，而 `gitRun` 对所有非零退出一律记 `error` 日志——探测类命令的预期失败被误记成错误。
- **状态**: 已修复（测试完成）
- **处理方法**: ① 输入 `GIT_QUEUES` 串行队列：`gitRun` 校验通过后经 `gitEnqueue(cwd, …)` 排队串行执行，杜绝同一仓库并发写锁；新增 `gitLockConflict(stderr)` 判定锁冲突、`removeStaleGitLocks(cwd)` 清除 `.git` 下残留 `*.lock`（`refs/HEAD/index` 等），`gitExecOnce` 首次遇锁冲突即清理并重试一次成功即返回。② 探测类命令（`status`/`rev-parse --abbrev-ref`/`remote get-url`）在 `git:check` 中传 `logFailure:false`，预期失败不再记错误日志；真正 git 操作失败（非零退出且非探测类）仍照常记日志。
- **验证结果**: `node --check` 语法通过；`npm test` 240 通过、0 失败。手动待验证：① 制造残留 `.lock` 后提交应自动清理并成功；② 无远程知识库探测不再写「git remote get-url」错误日志。
- **防再犯要点**: ① 凡面向同一仓库目录的 git 写命令（status/add/commit/push/checkout/reset 等）必须经**按 cwd 的串行队列**执行，观测到 `.lock ... File exists / cannot lock ref` 先清理残留锁再重试一次；② 纯探测类 git 命令（远程 url、分支名等）失败属预期状态，不应记错误日志（CD-49 新增）。
