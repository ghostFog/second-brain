# Bug-070 · 普通项目窗口 md 文档中的链接点击无效果

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-070
- **日期**: 2026-09-30
- **现象**: 「打开项目」工作区（普通项目窗口）里，md 文档中的内部链接（`[text](路径.md)` 相对路径）、`[[wiki]]` 链接点击后**毫无反应**（不新开页签也不报错）；外部 `https` 外链可正常用系统浏览器打开。
- **复现地点**: `second-brain/plugins/markdown-editor/md-linknav.js`（`refreshNotes` / `handleLink` / `findNoteByLink`）；该项目插件在普通项目窗口与知识库窗口共用。
- **原因**: `md-linknav.js` 的 `refreshNotes()` 固定用 `PluginAPI.editor.listNotes()`（底层 `noteStore.list()`，只列**知识库**笔记）填充 `notesCache`。而普通项目窗口没有知识库笔记（链接解析的清单里没有项目文件）→ `findNoteByLink()` 对项目相对路径/文件名恒返回 `null` → `handleLink` 走 `e.preventDefault()` 并在缓存空时 `refreshNotes()` 后 return，**不调用 openNote**，故内部/`[[wiki]]` 链接点击无效果。外部 `https` 外链走 `openExternal`（与笔记列表无关）所以原本可用。
- **状态**: 已修复（测试完成）
- **处理方法**: `md-linknav.js` 新增 `sbInProjectMode()` 判定；`refreshNotes()` 在项目模式下改从**项目文件树** `window.sbProject.list()` 取列表（`path` 为相对项目根的 rel 路径，与 `window.sbProject.read`/`PluginAPI.editor.openNote` 的项目读写契约一致），知识库模式仍走 `PluginAPI.editor.listNotes()` 不变。链接命中后 `openNote(rel)` 走既有 openNote 的项目模式内容装载分支（`editor-host.js` 已识别项目模式），相对路径按 `getState().current`（项目 rel 当前笔记）解析，`[[wiki]]` 按项目文件名匹配兜底。
- **验证结果**: `npm test` 252 通过、0 失败（基线 246 + 新增 6 条回归断言）；新增 `testMdLinkNavProjectMode` 覆盖：①源码 refreshNotes 项目模式分支调 `window.sbProject.list()`、知识库模式仍走 `api.listNotes()`；②项目 rel 链接（含同目录 `foo.md`）命中 → `openNote("docs/foo.md")` + preventDefault；③项目 `[[wiki]]` 链接按项目名命中 → openNote rel 路径；④外链 https → preventDefault + openExternal；⑤未命中 `.md` preventDefault 防 404。真机待验证：打开普通项目 → 打开含 `.md`/`[[wiki]]`/外链的 md 文档 → 点击应分别新开页签 / 新开页签 / 系统浏览器打开，知识库窗口链接行为不变。
- **防再犯要点**: ① 凡「根据链接/文件名找目标文件」的能力（`md-linknav.js` 链接导航等）在**多窗口复用**（知识库 + 普通项目共用）场景下，其**候选文件清单来源必须先判窗口模式**：项目模式从项目文件树 `window.sbProject.list()`、知识库从 `PluginAPI.editor.listNotes()`，禁止只喂知识库笔记列表让项目文件永远匹配不到（表现就是「链接点击无反应」）；② 项目模式与知识库共用「相对路径 rel 作为当前笔记路径」的契约被 `openNote` 内容装载分支识别，跨窗口复用编辑器能力时优先复用该契约 + 注入器伪造，不要为项目另起一套读写。
