# Bug-066 · 输入锁屏密码后仍提示输入笔记密码（锁屏未解锁时盐未定误判 locked）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（待真机验证）

- **ID**: Bug-066
- **日期**: 2026-09-26
- **现象**: 设置了应用锁屏密码、且当前库已启用笔记加密时，启动进入后输入锁屏密码成功，仍弹出「输入笔记加密密码」遮罩（#enc-unlock-screen）；即使该库的 M3（.second-brain/vault-enc.json）本可用锁屏密码盐正常解出（自动解锁），遮罩也不消失。
- **复现地点**: `main.js`（`app:encGetState` → `encNeedsUnlock`/`tryAutoNoteKey`）；`js/app-layout.js`（启动即调 `initVaultEncUnlock`）；`js/app-vault.js`（`initVaultEncUnlock` 仅启动检测一次）；`js/app-security.js`（`doUnlock` 解锁后未通知重检）
- **原因**: 启动阶段 `app-layout.js` 在 DOMContentLoaded 即调用 `initVaultEncUnlock()` → `enc.getState()`，此时锁屏尚未解锁，主进程 `encAppPwdPlain=null`（组合加密盐=固定盐 `shr25.com`）；而该库 M3 是「应用密码明文」做盐加密的（设置笔记密码时处于解锁态），固定盐解不出 M2 → `tryAutoNoteKey` 失败 → 误判 `locked=true` → 弹笔记密码遮罩。之后用户输入锁屏密码（`app:unlock` 把盐更新为密码明文）后，笔记密码遮罩**不会自动重新检测**，导致「明明已输入锁屏密码、库也能自动解锁，却还要再输一次笔记密码」。诊断确认：dfzx 库 M3 用固定盐与任意盐均解不开，仅锁屏密码盐可解（当天 21:03 用户设置/修改笔记密码时写入）。
- **状态**: 已修复（待真机验证）
- **处理方法**: 三处配合修复「盐未定时不误报 + 解锁后重检」——① `main.js` `app:encGetState`：锁屏密码存在且应用尚未解锁（`secPwdHash && !appUnlocked`）时 `locked` 一律返回 `false`（盐未定，不弹笔记密码遮罩）；② `js/app-vault.js` `initVaultEncUnlock`：检测逻辑重入化（`locked→show` / 否则 `hide`），暴露 `window.SBEncUnlock.recheck`；③ `js/app-security.js` `doUnlock`：锁屏解锁成功后调用 `SBEncUnlock.recheck()` 重新判定（此时盐=应用密码明文），能自动解锁则不再弹笔记密码遮罩。
- **验证结果**: `node --check main.js / js/app-vault.js / js/app-security.js` 语法通过；npm test 243 通过、0 失败。真机待验证：设锁屏密码 + 已加密库场景下，输入锁屏密码后不再弹笔记密码遮罩；M3 盐确实失效（如换设备无 M3）时仍能正常弹笔记密码输入并重建。
- **防再犯要点**: 笔记加密解锁的自动判定**依赖「应用密码明文作为组合加密盐」**，属于跨模块时序耦合——① 凡盐未定（锁屏未解锁）阶段的主进程判定都要显式豁免（返回 locked=false），不得用固定盐强行尝试导致误报；② 盐从「未定」变为「已定」（锁屏解锁）时必须提供渲染端重检钩子（SBEncUnlock.recheck），解锁成功即重新判定，避免遮罩滞留。
