# Bug-052 · 笔记内容被自动清空（文件只剩 1 字节换行）——vditor 首帧渲染完成前 blur 把空内容落入防抖保存。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-052
- **日期**: 2026-09-14
- **现象**: 用户某篇笔记（my 库《网络账号.md》）内容被自动置空，用户未手动删除；检查磁盘文件只剩 1 字节（单个换行符）。运行日志显示 10:27:23、11:18:37 两次打开该笔记时首帧补渲仅「1 字符」（磁盘上已是空内容），说明清空发生在更早的某次保存。
- **复现地点**: `js/editor/editor-vditor.js`（`buildVditor` 构建 + `blur` 回调）
- **原因**: `buildVditor` 在 `new Vditor()` 成功后立即执行 `vdBuffer = ''` 清空暂存缓冲；而 vditor 首帧渲染是**异步**的（`options.after` 触发前 `vdReady=false`）。在该窗口期内编辑器失焦（点击编辑区外/切换窗口/切笔记）触发 `blur` 回调 → `sync2Host(vdGetValue())` → `vdInst` 已存在但内部未就绪，`safeGetValue()` 抛错返回 `undefined` → 回退暂存缓冲 `vdBuffer`（已被清空为 `''`）→ `onEdInput('')` 把空内容写入 `edOutdated[path]` 并落入 800ms 防抖保存 → `noteStore.save(path, '')` 用空内容覆盖磁盘文件，笔记被静默清空。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. **`blur` 回调加 `vdReady` 守卫**：首帧异步渲染完成前（`vdReady=false`）直接 return，不触发内容同步，杜绝空内容进入防抖保存链路。
  2. **构建期不再清空 `vdBuffer`**：`vdBuffer` 恒为「最近一次 `vdSyncValue`/`vdSetValue` 的内容」，作为 `safeGetValue` 抛错时的兜底回退（回退到真实内容而非空串）；其值由下次同步覆盖，无残留风险。
- **验证结果**:
  - `regression.test.js` 新增 `testVditorBlurGuard`（桩 vditor 模拟首帧未就绪 getValue 抛错）：渲染完成前 blur 不触发保存；构建期 `vdGetValue` 回退缓冲得到真实内容；渲染完成后 blur 同步真实内容。`npm test` 163 通过、0 失败。
  - 语法检查 `node -c` 对 `editor-vditor.js`、`regression.test.js` 通过。
- **防再犯要点**: 第三方编辑器（vditor 等）实例重建/初始化期间（首帧异步渲染完成前）不得让失焦（blur）等回调触发内容保存；暂存缓冲在异步就绪窗口期不得清空，须保留最近一次同步内容作兜底（CD-39 新增）。
