# Bug-079 · 切换页签后 Ctrl+Z 回退串内容 → 宿主层 per-tab 独立历史栈 + Ctrl+Shift+Z redo

| 字段   | 说明                                                                                  |
| ---- | ----------------------------------------------------------------------------------- |
| ID   | Bug-079                                                                             |
| 日期   | 2026-10-26                                                                          |
| 现象   | **原始**：在 A 页签编辑后切到 B 页签，按 Ctrl+Z 回退时，B 的整个内容被替换成 A 的历史版本；Ctrl+Shift+Z（redo）完全无反应。 |
| 根因   | vditor 是全局单例（唯一 `vdInst`），原生 undo 栈挂在 `vdInst.vditor.undo.{ir,sv,wysiwyg}` 上，**所有 tab 共享同一套栈**。且 vditor 只内置了 Ctrl+Z 撤销和 Ctrl+Y 重做，Ctrl+Shift+Z 没有处理。 |
| 修复 v1 | **失败**：在 3 处 setValue 传 `clearStack=true`。解决了"串页签"但代价是"切走历史全丢"，不满足"每页签保留独立历史"需求。 |
| 修复 v2 | **失败**：save outgoing diff 栈 → setValue(clearStack=true) → restore incoming diff 栈。**根本行不通**——vditor undo 栈里的 patchList 是 diff_match_patch 的增量 diff，与当时的 DOM 状态和 lastText 紧耦合，restore A 的 patch 到 B 的 DOM 上结果完全错误。 |
| 修复 v3 | **最终方案**：宿主层 per-tab 文档快照历史 + 捕获阶段 keydown 拦截，见下。 |
| 状态   | 已修复（测试完成）                                                                   |
| 防再犯要点 | **CD-59**：单例富文本编辑器在切换文档/数据源时需要 per-tab 独立 undo 历史，**不能 save/restore vditor 原生 undo 栈**（diff 栈与当时 DOM 紧耦合，无法跨 DOM 状态恢复）。正确做法是放弃 vditor 原生 undo/redo，在宿主层用「整文档快照」维护 per-tab 历史栈，用捕获阶段 keydown 拦截 Ctrl+Z/Shift+Z/Y（先 preventDefault+stopImmediatePropagation 屏蔽 vditor 原生处理），调 setValue(snap, true) 回填。 |

---

## 最终方案

### 架构

```
vdLastTabPath: string | null                          // 追踪当前 active tab
vdTabHistory: { [path: string]: TabHistory }          // per-tab 历史栈
TabHistory = { undoStack: string[], redoStack: string[] }

// 关键函数
vdDebouncePush(path)    // input 回调 500ms 去抖 push 快照
vdDoPush(path, content) // 立即 push（切 tab 时用）
vdDoUndo(path)          // Ctrl+Z 执行 undo
vdDoRedo(path)          // Ctrl+Shift+Z / Ctrl+Y 执行 redo
```

### 时序

**输入时**（debounced）:
```
vditor input 回调 → vdDebouncePush(path) → 500ms 后 vdDoPush(path, vdInst.getValue())
```

**切 tab 时**（立即）:
```
renderArticle(B)
  → vdSyncValue(mdB, B)
    → pathChanged = (B !== vdLastTabPath=A) = true ✔
    → vdDoPush(A, vdInst.getValue())     // push outgoing 快照（切 tab 立即，不去抖）
    → h[B].redoStack = []                 // 清 incoming redo
    → h[B].undoStack.length === 0 时      // 首开 tab：把磁盘 md 作为「起始快照」
        h[B].undoStack.push(vdBuffer)
    → vdInst.setValue(mdB, true)           // 清空 vditor 原生 undo 栈（宿主层接管）
    → vdLastTabPath = B
```

**Ctrl+Z 时**:
```
keydown 捕获阶段 → 命中 Ctrl+Z
  → preventDefault + stopImmediatePropagation  // 屏蔽 vditor 原生处理
  → vdDoUndo(vdLastTabPath)
    → undoStack.pop() → redoStack.push(cur)
    → prev = undoStack[undoStack.length-1]
    → vdInst.setValue(prev, true)               // 回填宿主栈的上一份快照
```

**Ctrl+Shift+Z / Ctrl+Y 时**:
```
keydown 捕获阶段 → 命中 Ctrl+Shift+Z 或 Ctrl+Y
  → preventDefault + stopImmediatePropagation
  → vdDoRedo(vdLastTabPath)
    → redoStack.pop() → undoStack.push(next)
    → vdInst.setValue(next, true)
```

### 边界处理

| 场景 | 处理 |
|------|------|
| 首次打开 tab（无历史） | vdSyncValue 时把磁盘 md 作为起始快照 push，Ctrl+Z 时 undoStack.length < 2 返回 false，不执行 |
| Provider 切换（同内容换引擎） | `edCurrent` 没变 → `pathChanged=false` → 只 setValue，不动宿主历史栈 |
| 关闭 tab | `closeTabs` 调 `window.vdClearUndoCache(path)` 清理 `vdTabHistory` 和 `vdLastPushContent`，防内存泄漏 |
| 删除笔记后清空 | `vdSetValue` 重置 `vdLastTabPath = null` + 清理 debounce timer |
| 去抖期间切 tab | `vdPushDebouncePath` 与当前 path 不匹配，timer 到点时丢弃 |
| 分屏视图（vdPreview === 'both'） | destroy + rebuild 分支末尾补 vdLastTabPath 和 vdMarkFilled |

### 取舍说明

vditor 原生 undo 是**字符级 diff 栈**（patchList），粒度细但与 DOM 紧耦合，无法跨 DOM 状态 save/restore。宿主层方案用**整文档快照**（string[]），粒度粗但正确性高。VS Code、Notion 等主流编辑器也都用文档级 undo。
