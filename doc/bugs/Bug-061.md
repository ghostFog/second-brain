# Bug-061 · AI 问答「来源」出现 .gitignore（过滤文件误入向量库）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-061
- **日期**: 2026-09-15
- **现象**: AI 问答的回答「来源」列表中出现 `.gitignore`（相关度 57%），过滤文件内容进入了向量检索来源。
- **复现地点**: `second-brain/ai-engine.js`（`updateNote` 增量索引无隐藏路径过滤）+ `second-brain/plugins/git-sync/main.js`（`initRepo` 用 `notes:save` 写 `.gitignore` 触发 `updateNote`）
- **原因**: 元数据扫描 `_scanMd` 会跳过以 `.` 开头的文件/目录（.git、.obsidian、.second-brain 等），但**增量索引 `updateNote` 没有同样的隐藏路径过滤**，索引口径不一致。git-sync 插件初始化知识库时 `saveNote('.gitignore')` 走宿主 `notes:save` → `aiEngine.updateNote('.gitignore')`，把 `.gitignore` 文本分块、向量化后写进索引，`retrieve` 检索时被召回进「来源」列表。
- **状态**: 已修复（测试完成）
- **处理方法**: 新增 `_isDotPath(rel)` 统一判定（任一路径段以 `.` 开头即隐藏路径），与 `_scanMd` 口径一致，三处接入：①`updateNote` 入口跳过隐藏路径/非 `.md` 文件（不再建索引），且若该路径已有历史脏 chunk 则一并清除；②`_loadIndexFrom` 加载索引时即过滤历史误入的隐藏路径 chunk；③`retrieve` 余弦打分前兜底过滤，双保险。git-sync 侧无需改动（`notes:save` 写入 `.gitignore` 不再污染索引）。
- **验证结果**: `node --check` 语法通过；`npm test` 169 通过、0 失败；新增 3 条断言：`.gitignore` / `.second-brain/foo.md` 判定为隐藏路径、普通笔记路径不判定。手动待验证：重启应用进入 AI 问答提问，来源列表不再出现 `.gitignore`。
- **防再犯要点**: 凡写入/更新 vault 文件的路径，其**进入向量索引的入口（增量 updateNote、全量扫描）必须使用同一套隐藏路径判定**（任一路径段以 `.` 开头即跳过，含 `.gitignore`/`.obsidian`/`.second-brain` 等），且对历史已误入的脏数据要在索引加载/检索时兜底过滤，防止过滤文件、配置类文件污染检索来源（CD-48 新增）。
