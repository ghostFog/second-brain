# Bug-063 · 残留锁清理正则失效（master.lock 未命中）+ lucide 图标 compare 缺失

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-063
- **日期**: 2026-09-20
- **现象**: ① 上轮 Bug-062 的锁自愈未生效：实测提交仍报 `fatal: cannot lock ref 'HEAD': Unable to create '.../refs/heads/master.lock': File exists.` 且无自动清理重试效果；② 渲染控制台报 `<i data-lucide="compare" ...> icon name was not found in the provided icons object`。
- **复现地点**: `main.js`（`removeStaleGitLocks`）；`plugins/git-sync/manifest.json`（右键菜单「对比」图标）
- **原因**: ① `removeStaleGitLocks` 用正则 `/\.[0-9a-zA-Z-]+\.lock$/` 判断是否清残留，该正则要求「点 + 一串字母数字 + 点 + lock」。而真实锁文件名 `master.lock`/`HEAD.lock` 是**单点**结构（`xxx.lock`），根本不匹配，导致清理跳过、锁自愈始终不触发。② git-sync 右键菜单「对比」声明的图标名 `compare` 在本项目 lucide v1.8.0 内不存在真实键（只存在 `GitCompare`/`GitCompareArrows`/`Diff`/`FileDiff`），`createIcons` 找不到即报错。
- **状态**: 已修复（测试完成）
- **处理方法**: ① 锁文件清理正则改为 `/\.lock$/`（匹配任意以 `.lock` 结尾的文件），确认 `master.lock`/`HEAD.lock`/`packed-refs.lock` 均命中，配合 CD-49 的串行队列 + 冲突后重试一次性真正自愈。② manifest 图标 `compare` → `git-compare-arrows`（真实键 `GitCompareArrows`），消除 createIcons 缺失告警。
- **验证结果**: `node --check main.js` 通过；`/\.lock$/` 对 `master.lock/HEAD.lock/packed-refs.lock` 均返回 true；manifest JSON 解析通过；npm test 240 通过、0 失败。真机待验证：制造 `.git/refs/heads/master.lock` 后提交应自动清理并成功；右键「对比」不再打 lucide 缺失告警。
- **防再犯要点**: ① 涉及文件匹配的正则，必须用**真实文件名样例**验证（如 `master.lock` 是单点尾部 `.lock`，而非「点段.lock」），禁用只对理想形态成立的正则；② 插件/界面声明的 **lucide 图标名必须存在于实际打包的 lucide 包内**，改动后用包对象（`icons`）核对 `kebab-case` → PascalCase 键是否命中，不以「看着像」为准。
