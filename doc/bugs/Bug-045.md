# Bug-045 · 主题「一次设置、一次渲染」——插件启动不应再自动套用主题（与首帧重复设置）。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-045
- **日期**: 2026-09-10
- **现象**: 主题数据（宿主明暗 + minimal-theme 配色）本应「一次设置数据、一次渲染」：设置后持久化到 `localStorage`，启动/重启/切换时直接读取该数据渲染一次。但 minimal-theme 插件在启动时执行 `restore()` 主动 `applyTheme` 再套用一次主题，与 `index.html` head 首帧渲染重复、二次设置，造成不必要的重复渲染与潜在不一致。
- **复现地点**: `plugins/minimal-theme/main.js`（启动 `(function restore(){...})()` 自动 applyTheme）+ `index.html`（head 首帧按 `note-app:minimal-theme` 内联配色）
- **原因**: 主题的「设置」与「渲染」职责重复：head 已负责首帧渲染（读数据→内联到 `<html>`），插件启动却又走一遍 `applyTheme`（`clearCustomVars`→重构变量→`syncEditorTheme`），违背「一套数据、渲染一次」原则，且启动路径多一次状态写入/副作用。
- **状态**: 已修复（测试完成）
- **处理方法**: ① 删除 minimal-theme 插件启动 `restore()` 块——插件启动不再自动套用/二次设置主题，仅在用户主动切换（cycle/列表/设置变更）时 `applyTheme`+`syncEditorTheme` 渲染一次；② `index.html` head 首帧脚本在无显式历史选择时回退读取插件「默认配色方案」（`plugin:minimal-theme:defaultTheme`）兜底，保证新用户首帧也能一次渲染出默认配色（宿主明暗仍由 head 首块脚本负责）。
- **验证结果**: 新增回归 Bug-045 静态门禁（插件无 `restore()/applyIfReady/saved LocalStorage 读取`、head 含 `defaultTheme` 兜底且位于 `note-app:minimal-theme` 读取之后）；`npm test` 88 通过、0 失败。
- **防再犯要点**: 主题/外观类的「设置数据」与「渲染」应解耦：设置仅写入 `localStorage`，渲染统一由入口（head 首帧）读数据执行一次；插件侧不得在启动阶段再次 `applyTheme`（CD-31 新增）。凡新增主题维度，须只有一处「读数据→渲染」路径。
