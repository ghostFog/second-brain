# Bug-071 · 普通项目库下拉不显示当前项目 + 库下拉「最近打开」二级菜单悬浮收起异常

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-071
- **日期**: 2026-09-30
- **现象**:
  1. 切换到普通项目（普通项目窗口）后，打开库下拉，「当前项」仍显示**知识库**（默认兜底名「我的笔记库」），而非当前项目。
  2. 库下拉里悬浮「最近打开」展开二级菜单（临时文件列表）后，把鼠标**移出「最近打开」**（移到下拉其它项上），二级菜单**不收起**；只有把鼠标移出整个库下拉才收起。
- **复现地点**: `second-brain/js/app-vault.js`（`toggleVaultDropdown`：当前项渲染 + 「最近打开」二级菜单 hover 收起）。
- **原因**:
  1. 库下拉当前项无条件用 `window.noteDesktop.getVault()`（知识库信息）渲染「当前知识库」；普通项目窗口没有属主知识库 `getVault()` 返回空 → 落到兜底名「我的笔记库」，从不反映当前项目根。
  2. 「最近打开」二级菜单只在 **`dd`（整个下拉容器）`mouseleave`** 时收起。二级菜单是 `dd` 的**子节点**（`dd.appendChild(tm)`），鼠标在「最近打开」head 与二级菜单之间移动、或移到下拉其它项（都在 `dd` 子树内）都不会触发 `dd.mouseleave` → 二级菜单一直挂着，直到移出整个下拉才收（CD-05 同类：悬停子菜单仅靠父容器 mouseleave，缺乏对 head/二级菜单区域的边界与跨空隙处理）。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. 当前项渲染：`toggleVaultDropdown` 开头判定 `window.sbProject.isProjectMode()`；项目模式下经 `window.noteDesktop.project.current()` 取项目根绝对路径，`当前项` 显示**项目目录名**，标签「当前项目」、图标 `folder-git-2`；知识库模式维持原「当前知识库」逻辑不变。
  2. 二级菜单收起：把「仅整下拉 mouseleave 即时关」改为**延迟收起 + head↔菜单互 bridge**——离开「最近打开」head 或二级菜单先 `scheduleTempClose`（220ms 后移除），二级菜单自身 `mouseenter` 调 `cancelTempClose` 取消（横跨 head↔菜单 6px 空隙不闪关），移往其它项或下拉外即延迟收起。
- **验证结果**: `npm test` 257 通过、0 失败（基线 246 + Bug-070 6 条 + Bug-071 5 条）；新增 `testVaultDropdownProjectSubmenu` 覆盖：①项目模式当前项经 `project.current()` 取根；②项目模式标签「当前项目」/知识库「当前知识库」；③二级菜单延迟收起（220ms）；④二级菜单自身 mouseenter 取消延迟（桥间隙）；⑤移出 head 即延迟收。真机待验证：打开普通项目 → 库下拉当前项显示项目名「当前项目」；库下拉悬浮「最近打开」展开二级菜单 → 移到其它项/下拉外应收起，head↔菜单间移动应保持展开。
- **防再犯要点**: ① 标题栏库选择器等「当前实体」显示，须按**窗口模式**分流——项目模式取 `project.current()`（项目根目录名、标签「当前项目」），知识库模式取 `getVault()`（当前知识库），禁止项目窗口无条件读知识库 `getVault()` 落到兜底名；② 悬浮展开的**子菜单**（相对父容器 append、fixed 定位在父容器外/跨空隙）收起时机不能只依赖父容器整体 `mouseleave`——对子菜单悬停用「延迟关闭 + 子菜单 mouseenter 取消」的 bridge，离开 head/子菜单即收起，避免「移出 head 不关、移出整个下拉才关」的悬挂感（复用 CD-05 子菜单空隙 bridge 思路）。
