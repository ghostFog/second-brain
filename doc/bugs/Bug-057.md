# Bug-057 · 托盘知识库列表「我的笔记库」重复

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复

- **ID**: Bug-057
- **日期**: 2026-09-14
- **现象**: 托盘右键菜单的知识库列表中，「我的笔记库」出现两次（一处于顶部固定项，一处于历史库区）。
- **复现地点**: `second-brain/main.js`（`refreshTrayMenu` 的 `pushVault`）
- **原因**: `pushVault` 以键去重：第 1 步固定插入默认库用键 `'__default__'`；而第 3 步遍历历史库 `vaultHistory` 时，若曾打开过默认库，历史库里存的是默认库**实际路径**（`name='我的笔记库'`），其键为 `vaultKey(默认库路径)`，与 `'__default__'` 不相等，`seen` 去重失效，导致同一「我的笔记库」重复列出一条。
- **状态**: 已修复
- **处理方法**: `pushVault` 的键计算改为归一：默认库无论以 `null` 还是实际路径形式出现，统一解析为 `'__default__'` 键（`p == null || vaultKey(p) === defaultVaultRoot().toLowerCase()`），被第 1 步的 `seen` 拦截去重。
- **验证结果**: 语法检查通过；`npm test` 163 通过、0 失败。（托盘菜单依赖 Electron Tray 环境，未加可确定性复现的回归断言。）
- **防再犯要点**: 默认库的「身份标识」必须以同一索引用法判定——凡按库去重/归一的地方（托盘菜单、历史库、窗口绑定等），默认库要么用 `null`、要么用与实际默认库路径统一比较（`vaultKey(p) === defaultVaultRoot().toLowerCase()`），禁止出现「null 形式与路径形式键不同」导致同类条目去重失效（CD-44 新增）。
