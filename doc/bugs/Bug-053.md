# Bug-053 · 关闭主窗口报错「Object has been destroyed」+ 错误弹窗不可复制

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-053
- **日期**: 2026-09-14
- **现象**: 关闭主窗口时弹出系统错误对话框「A JavaScript error occurred in the main process / Uncaught Exception: TypeError: Object has been destroyed」，堆栈定位 `main.js:272:26`；该默认错误弹窗的文本**不可选中复制**，且错误不写入运行日志。
- **复现地点**: `main.js` `createWindow` 中 `win.on('closed')` 回调（第 272 行）
- **原因**: `closed` 事件触发时 BrowserWindow 已销毁，其 `webContents` 亦不可访问；回调内 `winVaults.delete(win.webContents.id)` 访问已销毁对象的属性，抛 `Object has been destroyed`。同文件 `focus` 回调也访问 `win.webContents.id`（窗口存活时安全，但属同类隐患）。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. **缓存窗口标识**：创建窗口时提前取 `const wcId = win.webContents.id`（窗口存活期内有效），`winVaults.set`、`closed`、`focus` 回调一律改用缓存的 `wcId`，不再访问已销毁的 `webContents`。
  2. **主进程异常接管**：新增 `process.on('uncaughtException')`（写 `userData/logs/app.log` + 弹**可复制错误窗口**）与 `process.on('unhandledRejection')`（仅落盘），替换 Electron 默认不可复制的系统错误弹窗。错误窗口用只读 textarea 承载堆栈（支持右键/全选复制），附日志完整路径与「打开日志目录」按钮（preload 新增 `noteDesktop.openLogDir` → IPC `shell:openLogDir`）。
  3. **托盘知识库列表（关联增强）**：托盘右键菜单动态列出全部知识库（默认库+当前打开库+历史库，去重、目录存在才显示），点击在对应库新主窗口打开（同库已有窗口则聚焦，单库单窗口）；窗口创建/关闭、库切换/迁移/移除时实时刷新（G-14）。
- **验证结果**:
  - 语法检查 `node -c` 通过（main.js / preload.js）；`npm test` 163 通过、0 失败。
  - 手动冒烟：启动应用（窗口「第二脑 — 09-03」）→ `CloseMainWindow()` 关闭主窗口 → 应用正常退出（exit 0），日志无 `uncaughtException` / `Object has been destroyed` 记录。
- **防再犯要点**: BrowserWindow 销毁后（`closed` 回调等）其 `webContents` 不可访问；任何事件回调/异步闭包访问窗口属性前，须在创建时缓存 `win.webContents.id` 等稳定标识，或先 `isDestroyed()` 校验（CD-40 新增）。
