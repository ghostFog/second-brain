# Bug-044 · 深色模式下编辑器表格首屏白色；点击 Ribbon 当前激活按钮会重渲染装载区。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-044
- **日期**: 2026-09-10
- **现象**: ① 设置深色模式启动应用后，编辑区内 `markdown` 表格为**白色**（与深色整体割裂），点击 Ribbon 导航栏「编辑器」按钮后才变成与主题一致的深色；② Ribbon 导航栏点击**当前已激活**的按钮仍会重新渲染视图装载区（重新装载/重建编辑器）。
- **复现地点**: `js/app-plugins.js`（`loadDirPlugins` 异步 fetch 插件 main.js + `registerEditorThemeResolver`）+ `js/editor/editor-vditor.js`（`resolveVdTheme` / `buildVditor` 读取 `extraCss`）+ `js/app-ribbon.js`（Ribbon 按钮点击路由守卫）
- **原因**: 两层。
  ① **表格白色（竞态）**：minimal-theme 插件把编辑器表格/引用/代码块的深色覆盖写成 `buildEditorCss`（`html body .vditor table ...`），经 `resolveVdTheme().extraCss` 注入。但 `initPluginSystem` 调 `loadDirPlugins()` **不 await**，插件 main.js 是异步 `fetch(note://local/...)` 执行；若 vditor 先于插件解析器注册而构建，`resolveVdTheme()` 读不到 resolver → `extraCss=''` → 表格回退到 vditor 浅色内容主题（白色）。点击编辑器按钮 = `loadView('editor')` → `vdDestroy` → 重建 vditor，此刻插件已加载、resolver 已注册 → `buildEditorCss` 生效 → 表格变深。
  ② **Ribbon 点击激活按钮重渲染**：启动时 `location.hash` 为空串，但 `getRoute()` 已按 fallback 显示编辑器（`activeView='editor'`）。Ribbon 点击守卫用**字面量**比较 `location.hash === btn.route`（`'' !== '#/editor'`）→ 误判「不在编辑器」→ `location.hash='#/editor'` → 触发 `hashchange` → `loadView` 重渲染装载区。
- **状态**: 已修复（测试完成）
- **处理方法**: ① `registerEditorThemeResolver` 注册 resolver 后立即调用宿主 `window.vdSyncTheme()` 重算并应用一次 vditor 主题（含 `extraCss` 表格深色覆盖）：无论 vditor 是否已构建都能补上，不再依赖「点击重渲染」纠正首屏白色；幂等、不引冲突。② Ribbon 按钮点击改为按「视图 key」归一化比较（`(location.hash||'#/editor').replace('#/','')` 对比 `btn.route.replace('#/','')`），当前视图已激活时不再触发 `hashchange` 重渲染装载区。
- **验证结果**: 新增回归 Bug-044-1（resolver 注册后触发 `vdSyncTheme`）、Bug-044-2（Ribbon 按视图 key 比较、不再字面量比较）静态门禁；`npm test` 86 通过、0 失败。
- **防再犯要点**: ① 主题/配色类的解析结果（如 vditor `extraCss`）若依赖异步加载的插件注册，负责应用方须在「注册完成后」主动补一次应用（注册即同步），不能只依赖用户再次进入/点击触发（CD-30 新增）。② 路由/视图的“已激活”判定应用归一化后的视图 key，不能用 `location.hash` 字面量比较，否则启动空 hash 会误触发重渲染。
