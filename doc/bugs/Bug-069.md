# Bug-069 · 开机后第一窗输入锁屏密码后编辑区空白，切换文件无效、换新窗才恢复

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：待定位

- **ID**: Bug-069
- **日期**: 2026-09-30
- **现象**: 电脑开机后第一次打开软件，输入完锁屏密码后，中间编辑区显示空白内容；切换目录区的文件，中间始终空白；切换知识库新开窗口则正常，关闭原空白窗口重新切换知识库后打开又正常显示。
- **复现地点**: `js/editor/editor-host.js`（`initEditor` 启动恢复 / `openNote` 内容装载与 `edOutdated` 缓存）/ `js/editor/editor-vditor.js`（`buildVditor` 首帧渲染 / `vdPending` 补渲）与锁屏时序（`js/app-security.js`、`js/app-vault.js`）
- **关联会话**: Bug-050（启动编辑器空白）、Bug-065（启动恢复失败留白）、Bug-066（锁屏密码时序）、Bug-067（密文检测修复）均为「待真机验证」，本报告疑似真机复现相关时序问题
- **原因**: 冷启动（开机后首次）时序竞态：编辑器装载与视图重建/插件重挂并发，`#ed-vditor` 容器可能被替换，旧 vditor 实例仍指向**已摘除节点**。对该实例 `setValue` 只写进脱离 DOM 的节点 → 界面恒空白（纯白、无内容）；且「切换文件」走 `setValue` 无法恢复（实例未重建），仅「换新窗 / 重启」（全新建实例挂到当前容器）才能恢复——与该现象「仅冷启动首次、纯白、切文件无效、重建即恢复」完全吻合。应用锁屏用 `visibility:hidden`（保留布局尺寸），排除「尺寸为 0」；无笔记加密，排除「盐时序返回密文」。
- **状态**: 已修复（待真机验证）
- **处理方法**: 在 vditor 实例统一出口 `ensureVd` 加「容器脱离文档自愈重建」守卫：若 `vdInst.vditor.element.isConnected === false`（旧实例根节点已被摘除），销毁并重建到当前 `#ed-vditor`，并让 `vdSyncValue` 改经 `ensureVd` 懒创建（替换原先 `if (!vdInst) buildVditor()`），使切换文件/渲染也能检测到失效实例而重建。改动集中在 `js/editor/editor-vditor.js`：
  ```js
  // ensureVd
  const root = vdInst && vdInst.vditor && vdInst.vditor.element;
  if (vdInst && root && root.isConnected === false) {
    // SBLog.warn 记录后 destroy、置 null、vdReady=false
  }
  if (!vdInst) buildVditor();
  // vdSyncValue 开头由 ensureVd() 取代 if (!vdInst) buildVditor()
  ```
- **验证结果**: `node --check` 通过；`npm test` 245 通过、0 失败（新增 2 条 Bug-069 断言：实例容器脱离文档时 `vdSyncValue` 触发自愈重建、重建沿用当前编辑节点 mode）。真机待验证：开机冷启动首次进入不再空白；即便进入瞬间存在竞态，切换任意笔记（触发 `vdSyncValue→ensureVd`）也能自愈恢复。
- **防再犯要点**: CD-54（已回填 `doc/bugs/防再犯清单.md`）
