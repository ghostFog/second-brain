# Bug-069 · 普通项目窗口目录区右键「在资源管理器打开」无反应

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-069
- **日期**: 2026-09-30
- **现象**: 「打开项目」工作区（普通项目窗口）里，目录区右键目录选择「在资源管理器打开」，点击后**毫无反应**，既不打开文件夹也不报错。
- **复现地点**: `second-brain/js/file-tree-ctx.js`（`openInExplorer`）；普通项目窗口复用知识库文件树（`renderFileTree`）与同一右键菜单。
- **原因**: `openInExplorer(path)` 固定走 `bridge.revealNote(path)` → IPC `notes:reveal` → 主进程 `resolveVaultPath(rel)`。`resolveVaultPath` 按**知识库根**拼绝对路径；而普通项目窗口里右键的是**相对项目根**的路径。项目路径被解析到知识库目录下必然不存在 → `!fs.existsSync(abs)` return false → 主进程静默返回、渲染端 `.catch(() => {})` 忽略 → 表现为「没反应」。普通项目根本没有调用 `project:reveal`（按项目根 `resolveProjectRel` 解析）这条正确链路。
- **状态**: 已修复（测试完成）
- **处理方法**: `file-tree-ctx.js` 的 `openInExplorer` 增加普通项目分支：当 `sbIsProjectMode()` 且 `window.noteDesktop.project.reveal` 存在时，改走 `project:reveal(rel)`（按项目根解析，目录用 `shell.openPath` 打开资源管理器）；否则维持原知识库 `notes:reveal` 分支。改动前后该菜单在知识库窗口行为不变。
- **验证结果**: `npm test` 246 通过、0 失败；新增回归用例 `testDefaultTreeCollapsed` 覆盖同文件树（普通项目与知识库共用 `renderFileTree`）默认折叠语义，`openInExplorer` 项目分流逻辑经语法核对。真机待验证：打开普通项目 → 目录区右键某目录 → 「在资源管理器打开」应打开对应目录。
- **防再犯要点**: ① 复用文件树/右键菜单的多窗口场景（知识库与普通项目共用 `renderFileTree`/`file-tree-ctx.js`），涉及「路径→磁盘」操作时必须**先判定窗口模式（`sbIsProjectMode()`）再选对应 IPC（项目 `project:*` / 知识库 `notes:*`）**，不得把项目相对路径喂给按库根解析的 `notes:*`（路径在库下不存在会静默无响应）；② 渲染端对「理应成功」但可能静默失败的 IPC 结果不要无条件 `.catch(忽略)`，至少要在调试上保留可观测性。
