# Bug-068 · AI 索引库列表同一知识库重复（历史索引算法残留未清理）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（待真机验证）

- **ID**: Bug-068
- **日期**: 2026-09-26
- **现象**: AI 问答「索引库」下拉列表出现**同一知识库两条**（dfzx · 22 块 与 dfzx · 28 块，时间相同），两行都 only 提供「重建」按钮、无删除入口，用户无法自助清理；检索时当前库读的是 dr30tz 索引，旧索引为冗余数据。
- **复现地点**: `%APPDATA%\second-brain\ai-index\` 下存在 `6qb8ht.index.json`（22 块，noteIndexAt 增量更新停留在 2026/9/25 11:10）与 `dr30tz.index.json`（28 块，noteIndexAt 至 2026/9/26 22:23），两者 `vaultPath` 均为 `D:\BaiduSyncdisk\my\second-brain\dfzx`、`builtAt` 同为 2026/9/17 19:32:45；`ai-engine.js` `listIndexes` 按**文件名**逐条列索引文件、不按 vaultPath 去重。
- **原因**: 索引按库分文件的 key 由 `_vaultKeyFor(root)`（绝对路径小写 DJB2）生成。9/17 19:32:45 应用升级/迁移索引算法时，新旧两套 key 算法各为该库写了一个索引文件（`6qb8ht`=旧算法产物、`dr30tz`=当前算法产物）；旧文件未被删除，且旧版本进程一直增量更新 `6qb8ht` 直到 9/25 升级停止——此后 `listIndexes` 把两个文件都列成条目 → 同名 dfzx 重复。两个文件 `builtAt` 相同说明迁移点同一时刻新旧各写一次。
- **状态**: 已修复（待真机验证）
- **处理方法**: ① 立即清理：删除 `%APPDATA%\second-brain\ai-index\6qb8ht.index.json`（旧算法残留，当前版本不再读取），保留 `dr30tz.index.json`；或在索引库面板点任意 dfzx 行「重建」（见下自愈）。② 自愈修复 `ai-engine.js`：新增 `_pruneStaleIndexFor(root, keepKey)`——按 vaultPath 匹配删除该库路径下、文件名 key ≠ 本次 keepKey 的旧索引文件（复用 `deleteIndex` 的匹配口径，只删同路径旧文件、不动其他库）；`rebuildIndex`（重建当前库）与 `rebuildIndexFor`（重建指定库）在写盘**前**调用，重建一次即收敛为单一索引文件，重复条目自动消失。
- **验证结果**: `node --check ai-engine.js` 语法通过；npm test 243 通过、0 失败；临时自测（临时目录构造同库两 key 文件 + 其他库文件 → `_pruneStaleIndexFor` 只删同库旧 key、保留 keepKey 与其他库）PASS。真机待验证：重启应用后在索引库面板点 dfzx「重建」→ 列表只剩一条 dfzx；或直接删 `6qb8ht.index.json` 后重启列表即剩一条。
- **防再犯要点**: ① 索引文件按库分文件命名（key 哈希）的**算法变更/升级时，必须先迁移清理旧命名文件再写新文件**，禁止新旧并存；② 任何「按库分文件」的目录清单展示都应**按业务键（vaultPath）去重/归并**，不能按文件名单条平铺；③ 重建类操作写盘前应自愈清理同库旧文件（`_pruneStaleIndexFor`），避免遗留冗余索引。
