# Bug-073 · 项目窗口新建目录落入知识库且目录区被重绘为知识库内容

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-073
- **日期**: 2026-10-09
- **现象**: ①在一般项目（项目窗口）目录区右键「新建目录」，目录被建到**上一次打开的知识库**里；②新建后整个目录区**变成了知识库的目录树**（新目录出现在知识库树里），项目文件树丢失；③打开一般项目时目录区显示的不是项目内容（无内容/知识库内容）。同菜单的「新建笔记」同病：会写进知识库。
- **复现地点**: `second-brain/js/editor/editor-filetree.js`（`doNewFolder`/`doNewNote`）、`second-brain/js/file-tree-ctx.js`（`refreshTreeAfterChange`）、项目窗口共用知识库文件树与右键菜单。
- **原因**: 项目模式只是「读/写文件」两级接了项目 IPC（`project:read/save`），目录树右键的**写操作全部仍走知识库 `noteStore`**：`doNewFolder → noteStore.createDir`（`notes:createDir` 按当前窗口解析的知识库根落盘）把目录建进知识库；创建后 `noteStore.list()` 返回知识库笔记列表重绘 `renderFileTree`，整个目录区被替换成知识库树。`refreshTreeAfterChange`（删除/移动/重命名后的统一刷新收口点）同样无条件 `noteStore.list()`。此外项目目录条目（`isFolder=true`）不参与 `renderFileTree` 目录节点构建，空目录（子树内无文件）在项目树里不可见，新建空目录后「看不到」加重了误判。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. `main.js` 新增 IPC `project:createDir`（项目根下 mkdir 递归，`resolveProjectRel` 防越权）、`project:openExternal`（`shell.openPath` 系统默认程序打开，见 Bug-074）；`preload.js` 暴露 `project.createDir/openExternal`。
  2. `editor-filetree.js` `doNewFolder`/`doNewNote` 增加项目分支：分别走 `sbProject.createDir`（多级递归建目录）与 `sbProject.saveRel(rel,'')`（写空文件，同名自动追加序号），完成后 `sbProject.refresh()` 重绘**项目**树；知识库分支原样保留。
  3. `file-tree-ctx.js` `refreshTreeAfterChange` 顶部增加项目分支：`sbIsProjectMode()` 时走 `sbProject.refresh()`（收口点，删除/移动/重命名后的刷新不再误拉知识库列表）。
  4. 防误伤守卫（同根因、防数据事故）：项目模式下 `actDeleteNote/actDeleteDir/actMoveNote/actMoveDir/renameNoteFile/renameDirInline/rebuildMeta` 一律提示「项目模式暂不支持，请在系统资源管理器操作」并返回，避免按知识库相对路径误删/误改库内同名文件。
  5. `editor-filetree.js` `renderFileTree` 目录节点构建补充：`isFolder=true` 条目自身注册为目录节点，空目录在项目树可见。
- **验证结果**: `npm test` 275 通过、0 失败（新增 `testProjectModeTreeRouting`：jsdom 行为断言新建目录路由 `project:createDir` 且零触 `noteStore.createDir`、新建笔记路由 `project:save` 自动补 `.md`、空目录注册进树数据并可展开渲染；源码断言刷新收口/守卫/新 IPC）。真机 CDP 验证：项目窗口 `sbProject.createDir('docs/新建目录A')` 磁盘落点=项目根下 `docs/新建目录A`（存在），dfzx/my 两个知识库根均无误建；刷新后树数据含新目录；`refreshTreeAfterChange` 含项目分支。
