# Bug-065 · 打开笔记报未处理 Promise 异常（errors notes:read EISDIR: illegal operation on a directory）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（待真机验证）

- **ID**: Bug-065
- **日期**: 2026-09-22
- **现象**: 控制台报 `[error] 未处理 Promise 异常: Error invoking remote method 'notes:read': Error: EISDIR: illegal operation on a directory, read`。
- **复现地点**: `main.js`（`vaultHandle('notes:read')`，读单篇笔记原文）；`preload.js`（`readNote`）；`js/editor/editor-host.js`（`openNote` 内容装载分支）
- **原因**: 有目录路径被当作笔记传给 `notes:read`，主进程 `fs.promises.readFile(目录路径, 'utf8')` 直接抛裸 `EISDIR`；且渲染端 `openNote` 的 `await noteStore.read(path)` 未捕获该拒绝，异常沿调用栈上抛到无 `.catch` 的事件处理器，形成「未处理 Promise 异常」。目录会进 `openNote` 的根因：最近打开（`recent.json`）等开放路径恢复时可能把历史目录项或误判路径当作笔记打开。
- **状态**: 已修复（待真机验证）
- **处理方法**: 两处边界防护——① `main.js` 的 `notes:read` 先 `lstat` 判定：目标是目录时抛出清晰错误（`EISDIR: 目标是目录而非笔记文件，无法读取: rel`），不直接裸读目录；② `editor-host.js` 的 `openNote` 内容装载加 `try/catch`：读取失败时撤销刚压入的页签并 `renderTabs()` 后返回，避免「未处理 Promise 异常」和打不开的幽灵页签，并 `console.error` 记录原因。**后续回归修复（编辑器空白）**：`.git` 等点开头目录被 `walkNotes` 当作空目录输出进笔记列表，且曾进过最近打开，启动恢复时把它当最后 tab 打开——失败被 ② 的 catch 吞掉后 `return`，`edCurrent` 仍为 null → 编辑器正文留白。再补两处：③ `main.js` 的 `walkNotes` 跳过 `name.startsWith('.')` 的隐藏项（`.git`/`.obsidian`/`.github`），根治目录混入笔记列表；④ `openNote` 的 catch 在「当前无任何笔记打开」时回退打开 `edNotes[0]` 首个真实笔记（回退目标与失败路径相同时不再递归），杜绝静默留白。**预览行号残留再兜底**：⑤ 配置层面 `preview.hljs.lineNumber:false`（L1159）生效中，但旧构建/未重建的 vditor 实例可能残留 `.vditor-linenumber` 节点，故在 `css/app.css` 末尾加 CSS 强制隐藏 `.vditor-linenumber(_rows)` / `hljs-ln` / `hljs-line-numbers`（`display:none!important`），保证预览代码块绝不出现不规则行号。
- **验证结果**: `node --check main.js / editor-host.js` 语法通过；npm test 243 通过、0 失败。真机待验证：① 旧目录路径场景不再报 EISDIR 未处理异常、不残留幽灵页签；② `.git` 等点目录不再进笔记列表；③ 启动恢复正常显示笔记（不再空白），引用的 `.git` 等失效 tab 会回退打开真实笔记。
- **防再犯要点**: ① 所有 IPC 读文件边界都要先做**目录判定**（`lstat().isDirectory()`），用清晰错误取代 Node 裸 `EISDIR`；② 渲染端 `await` 任何可能失败的异步读（IPC/引擎）都要 `try/catch`，失败的路径要回滚到安全状态（本例撤销页签再返回），禁止让拒绝上抛成「未处理 Promise 异常」。
