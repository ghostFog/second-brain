# Bug-060 · 嵌入式模型库启动后不显示「已使用」

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-060
- **日期**: 2026-09-15
- **现象**: 设置页「AI 问答—嵌入式模型库」已把某模型设为嵌入/重排序路径，但**应用启动后模型卡片不显示「已使用」**，仍显示可点的「使用」按钮。
- **复现地点**: `second-brain/js/settings/settings-ai.js`（`renderLibBox` 的 `inUse` 判定 / 初始化时序）
- **原因**: 「已使用」判定 `inUse = local && activePath === localPath` 依赖输入框 `embedModelPath` 的值（`cfgPathValue` 展开 `{modelDir}` 后与本地检测出的 `localPath` 比较）。而两条异步链顺序不定：`loadModelLib()`（`getModelLib` 扫描本地模型 → `renderAllLib`）与 `ai.getConfig().then(fillLocal)`（回填输入框）为**并行独立异步**。当 `renderAllLib` 先于 `fillLocal` 执行时，输入框尚未回填、`cfgPathValue` 得空串，`activePath==='' !== localPath` → 判定不到「已使用」，且回填完成后不再重绘，错误状态被保留。
- **状态**: 已修复（测试完成）
- **处理方法**: 在 `ai.getConfig().then(fillLocal(cfg))` 输入框回填之后主动补一次 `renderAllLib()`：若 `getModelLib` 已完成则立即修正「已使用」；若尚未完成，则本次渲染为空、随后 `loadModelLib` 的 `then(renderAllLib)` 在输入框已回填的基础上渲染出正确状态。两种顺序下最终都正确。
- **验证结果**: `node --check` 语法通过；`npm test` 163 通过、0 失败；逻辑覆盖「渲染先于回填 / 回填先于渲染」两种时序均收敛到正确「已使用」。手动待验证：启动后进入设置页，已配置的嵌入/重排序模型应显示「已使用」。
- **防再犯要点**: 渲染结果若依赖「输入框/配置值」的解析，而回填该值（fillLocal）与实际渲染（renderAllLib）又分属**不同的并行异步链**（如 `getConfig` 回填 vs `getModelLib` 扫描），必须在**配置回填完成后主动重绘一次**，不得只依赖异步结果链自身触发——否则竞态下「由配置驱动显示的状态」（如「已使用」）会丢失且不再刷新（CD-47 新增）。
