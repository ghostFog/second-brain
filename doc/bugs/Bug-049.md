# Bug-049 · IR（即时渲染）模式通用右键菜单永不弹出——代码块判定误用 `closest('pre')` 把整区短路。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-049
- **日期**: 2026-09-12
- **现象**: 编辑区右键「插入图片 / 上传附件」通用菜单（`.sb-ctx`）在所见即所得（WYSIWYG）模式下正常弹出，但在即时渲染（IR）模式下对普通文字右键始终不出现；IR 表格/代码块专属菜单正常。
- **复现地点**: `js/editor/editor-vditor.js`（`onEditorContextMenu` 内 `if (vdMode === 'ir')` 的短路分支）
- **原因**: Bug-048 修复后命中判定已改用 `vdInst.vditor.element`（右键入口能进到 IR 分支），但 IR 分支用于「把表格/代码块右上交给专属菜单、避免叠加」的短路条件用了 `el.closest('table, pre')`。而 **vditor IR 会把整个编辑区内容包在一个 `<pre class="vditor-reset">` 里**，普通文字也命中 `pre`，导致每次右键普通文字都被误判为「代码块」而 `return` 短路；通用菜单势分支（`e.preventDefault()` + `showSbMenu`）永不执行。WYSIWYG 无该 `<pre>` 包裹、且 `vdMode !== 'ir'` 不进入此分支，故只有 IR 受影响。
- **状态**: 已修复（测试完成）
- **处理方法**: 移除 `pre` 短路，代码块判定改为命中真实代码块节点的 `data-type` 属性：
  ```js
  if (el && typeof el.closest === 'function'
    && (el.closest('table') || el.closest('[data-type="code-block"]'))) return;
  ```
  与 `irCodeAtRightClick` 的判定口径一致（`[data-type="code-block"]` 内 `<pre><code>`），普通文字不再命中 `pre`，通用菜单分支恢复执行。
- **验证结果**: CDP 实机（web 版 IR 模式）注入含「普通段落 + 代码块」内容后分别右键：
  - 普通段落右键 → 弹出 `.sb-ctx`，含「插入图片」「上传附件」两项；`onEditorContextMenu` 命中 `vdMode=ir, rootHasTarget=true` 并执行 `showSbMenu(items=2)`。
  - 代码块右键 → 正常弹出 `#ed-ir-table-menu` 代码菜单「在上方插入空行」，不与通用菜单叠加。
  `regression.test.js` 新增 2 条断言（IR 代码块判定用 `[data-type="code-block"]` 且短路条件不再含 `pre`），`npm test` 139 通过、0 失败。
- **防再犯要点**: 判断 vditor IR 编辑区内是否「代码块」时，必须用代码块节点自带的 `data-type`（如 `[data-type="code-block"]`）判定，**不得用 `closest('pre')`**——IR 把整个编辑区包在一个 `<pre class="vditor-reset">` 里，普通文字也命中 `pre`，会误短路通用逻辑（CD-36 新增）。
