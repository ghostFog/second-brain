# Bug-075 · 项目窗口打开文本文件编辑区空白（.sql 等），且非 md 文本无高亮

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-075
- **日期**: 2026-10-09
- **现象**: 项目窗口（哈电运维）打开 `2026/05/20260506/20260506.sql`：页签已开、`ed-count` 字数正常、无任何报错，但编辑区完全空白。用户同时要求：所有文本格式文件都应走普通编辑器，非 md 文本（.sql/.json/.py 等）的高亮复用现有代码块高亮。
- **复现地点**: `second-brain/js/editor/editor-vditor.js`（`buildVditor` 静默放弃分支）、`second-brain/js/editor/editor-host.js`（`renderArticle`/`onEdInput`）、`second-brain/main.js`（`project:read` 二进制判定）。
- **原因**（三层）:
  1. **编辑区空白根因**：主进程启动时 `session.clearCache()` 与渲染端 vditor 脚本（`node_modules/vditor/dist/index.min.js`）加载存在竞态，`window.Vditor` 可能未定义；`buildVditor` 对「容器存在而 Vditor 未定义」的处理是**静默放弃且永不重试**（只保留 vdBuffer），该窗口编辑区从此永久空白。此外 `new Vditor(...)` 同步抛错走 catch 后同样无重试。
  2. **无高亮承载**：项目内 .sql/.json 等文本文件在编辑器中按纯文本展示，无代码高亮。
  3. **文本误判二进制**：`project:read` 以「内容含 NUL 即二进制」判定，UTF-16（LE/BE BOM）文本文件被误杀调系统程序打开，违背「文本格式都走普通编辑器」。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. `editor-vditor.js`：`buildVditor` 在「el 存在而 `window.Vditor` 未定义」时改为 500ms 间隔延迟重试构建（60 次上限 30s，重试成功后 vdBuffer 中待渲内容随 value 装载）；jsdom 回归沙箱跳过重试（不依赖真实定时器）。
  2. `editor-host.js`：新增 `PROJ_CODE_LANGS` 后缀→hljs 语言映射与 `projCodeLangOf/sbProjFenceWrap/sbProjFenceUnwrap`；`renderArticle` 对项目模式非 md 文本按后缀包 ```lang fence 进 vditor（复用现有代码块 hljs 高亮），`onEdInput` 落盘/缓存入口统一解包（磁盘恒为原文）；代码文件强制 IR 模式打开（代码块高亮仅 IR/WYSIWYG 渲染，SV 源码面板无高亮）。注意 `fileExtension` 返回带点后缀（'.sql'），映射前需去点。
  3. `main.js`：`project:read` 优先按 UTF-16 LE/BE BOM 解码文本（binary=false），无 BOM 且含 NUL 才判二进制。
- **验证结果**: `npm test` 286 通过、0 失败（新增 `testProjectCodeFileHighlight`：Bug-075-1~5 源码断言重试/包装解包/BOM 判定，Bug-075-7~12 行为断言 `__sbProjFence` 往返无损）；真机 CDP 验证：项目窗口打开 .sql 后 `language-sql` 高亮 DOM 与代码块 DOM 存在、vditor 内容为 ```sql 包装态、md 文件不受影响、blur 回灌后磁盘 SHA256 不变（解包防回灌生效）。
