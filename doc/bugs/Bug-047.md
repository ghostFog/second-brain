# Bug-047 · Ribbon 高亮态未按视图归一化——切回编辑器时左侧导航不激活。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-047
- **日期**: 2026-09-11
- **现象**: 主界面激活「编辑器」视图时（切到图谱/插件/AI 视图后再切回编辑器，或启动后进入编辑器），左侧 Ribbon 的「编辑器」按钮没有被高亮激活，其它视图却能正常高亮。
- **复现地点**: `js/app-ribbon.js`（`updateActive`）+ `js/app-layout.js`（`loadView`→`updateNav`）+ `js/app-core.js`（`updateNav` 委托 `RibbonManager.updateActive`）
- **原因**: 内置「编辑器」Ribbon 按钮的 `id` 用的是 `file`（`BUILTIN_BUTTONS` 定义），而视图切换走路由 key（`loadView('editor')` 传入 `'editor'`）。`updateActive(navKey)` 直接以 `el.dataset.ribbonBtn === navKey` 匹配，切回编辑器时传入 `'editor'`，但按钮的 `data-ribbon-btn` 是 `'file'`，两边不匹配 → 编辑器按钮永远不激活。其余视图（graph/plugins/settings/ai）的按钮 id 与路由 key 一致，故只有编辑器受影响。
- **状态**: 已修复（测试完成）
- **处理方法**: 统一内置「编辑器」Ribbon 按钮 id 直接改为 `'editor'`（与路由 key 及 `init` 默认值一致），删掉原先的 `'file'`：`BUILTIN_BUTTONS` 中 id 改 `'editor'`、`init` 默认值 `navKey || 'editor'`、`app-layout.js` 启动 `RibbonManager.init('editor')`。这样 `updateActive` 直接以 `dataset.ribbonBtn === navKey` 匹配即可命中编辑器按钮，无需归一环。
- **验证结果**: 新增回归断言 Bug-047-1（编辑器按钮 id 为 `editor`、`init` 默认值为 `editor`、`updateActive` 直接匹配 `dataset.ribbonBtn === navKey` 且不再含 `editor→file` 归一化）；`npm test` 97 通过、0 失败。
- **防再犯要点**: Ribbon/导航内置按钮的 id 必须与视图路由 key 保持一致（如编辑器用 `editor`），不要另起别名（如 `file`），否则以路由 key 驱动高亮时会匹配失败（CD-34 修正）。
