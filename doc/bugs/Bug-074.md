# Bug-074 · 项目窗口点击二进制/未支持后缀文件无法打开（应调系统默认程序）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-074
- **日期**: 2026-10-09
- **现象**: 一般项目（项目窗口）目录区点击二进制/未支持后缀文件（如 .png/.zip/.exe 等非文本文件）：①经页签/树入口打开时仅 toast「二进制文件不可编辑」，不打开任何东西；②经 `openNote` 内容装载路径进入时把二进制内容当文本塞进编辑器（乱码）。均没有「用系统默认程序打开」的途径。
- **复现地点**: `second-brain/js/project-mode.js`（`sbProjectOpenNote` 二进制分支）、`second-brain/js/editor/editor-host.js`（`openNote` 内容装载）、`second-brain/main.js`（缺系统打开 IPC）。
- **原因**: 项目模式 `project:read` 已返回 `binary` 标记，但渲染端两条打开路径都只「拒绝进编辑器」：`sbProjectOpenNote` 二进制分支仅提示后 return，`openNote` 直接把 `.content` 写入编辑器缓存；主进程没有暴露 `shell.openPath` 的项目 IPC，无法调起系统默认程序。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. `main.js` 新增 IPC `project:openExternal`（`resolveProjectRel` 解析 + 存在性校验后 `shell.openPath`，返回空串=成功）；`preload.js` 暴露 `project.openExternal`；`project-mode.js` 封装 `sbProject.openExternal(rel)`。
  2. `project-mode.js` `sbProjectOpenNote`：二进制分支改为 toast「已调用系统默认程序打开」+ 调 `sbProject.openExternal`；读取失败显示 `r.error`。
  3. `editor-host.js` `openNote` 项目模式装载前先 `sbProject.read` 探测 `binary`：二进制则撤销刚压入的页签（不留幽灵页签）后 `openExternal` + toast，不进编辑器。
- **验证结果**: `npm test` 275 通过、0 失败（`testProjectModeTreeRouting` 内 Bug-074-1~3 源码断言 IPC/封装/分支存在，Bug-074-4~5 行为断言二进制文件调 `project:openExternal` 且不进 `openNote`）；真机 CDP 验证：项目内 .png 读取返回 binary=true、`sbProject.openExternal` 可调。
- **防再犯要点**: 见 `doc/bugs/防再犯清单.md` CD-55。
