# Bug-055 · Git 回滚后编辑器仍显示旧内容且被失焦自动保存写回，造成回滚无效与内容被覆盖/置空

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（待手动验证）

- **ID**: Bug-055
- **日期**: 2026-09-14
- **现象**:
  1. 右键 Git 二级菜单「回滚（放弃修改）」（或整库还原）执行后，磁盘文件已回滚，但编辑器仍显示回滚前的内容（编辑器与磁盘不一致）。
  2. 随后 vditor 失焦（blur）自动保存会把编辑器里的**旧缓存内容**（甚至空内容）写回磁盘文件，导致回滚「没有实际回滚」、笔记内容会被旧值/空覆盖置空。
- **复现地点**: `plugins/git-sync/main.js`（`revertWorkingFile` / `doRevert`）+ 宿主 `js/editor/editor-host.js`（`onEdInput` 失焦自动保存、`edOutdated` 缓存）
- **原因**: `git checkout -- <relPath>` 只改写磁盘；编辑器以 `edOutdated[path]` 缓存为权威且回滚后未失效。vditor 失焦 `blur → sync2Host → onEdInput` 会把旧缓存（或空）内容自动写回磁盘，覆盖回滚结果。
- **状态**: 已修复（待手动验证）
- **处理方法**:
  1. 宿主新增 `PluginAPI.editor.reloadNote(path)`：清 `edOutdated[path]` + `edDirty.delete(path)`；若该文件正是当前打开文件则重新 `openNote` 从磁盘重读重渲染。
  2. 插件 `revertWorkingFile` / `doRevert` 成功后调用 `reloadNote`，把编辑器刷新到磁盘真实内容。
  3. 宿主 `onEdInput` 增加守卫：**内容与已缓存一致且非脏文件时不再写文件**——只有确实发生内容变化的手动修改才触发自动保存，杜绝失焦/程序性重复写把旧/空内容覆盖回磁盘（满足「只有手动修改内容才写入文件」）。
- **验证结果**: 语法检查通过；`npm test` 163 通过、0 失败。回滚后编辑器刷新与「不改则不写回」由用户手动交互验证。
- **防再犯要点**: 外部改动知识库磁盘文件（Git 回滚/还原等）后，必须**主动失效缓存并重载编辑器**到磁盘最近内容；编辑器自动保存只应在「内容相对已缓存且非脏」发生变化时才写盘，防止失焦/程序回灌把旧/空内容覆盖回磁盘（CD-42 新增）。
