# Bug-043 · Minimal Theme 配色首屏仍闪宿主默认色；内置配色依赖异步样式；「停用」档冗余。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-043
- **日期**: 2026-09-10
- **现象**: ① 内置配色（纸白/亚麻/冷灰/墨绿）或自定义配色启动时仍闪：首帧为所选配色 → 短暂闪成宿主深/浅默认色 → 再闪回配色；② 配色列表/循环中存在冗余的「停用」档；③ **编辑器区域**启动时闪：先用暗色（`vditor--dark`）渲染 → 再由插件回套浅色。
- **复现地点**: `plugins/minimal-theme/styles.css`（内置配色唯一数据源，fetch 异步注入）+ `plugins/minimal-theme/main.js`（`applyTheme`/`applyCustomVars`）+ `js/app-plugins.js`（插件样式异步加载）+ `index.html`（首屏 head 前置恢复）
- **原因**: 两层叠加。① 配色应用目标不一致：minimal 配色（`mt-theme-N` class / custom 内联变量）挂在 **body**，而宿主 head 首屏脚本只恢复宿主明暗（挂 `<html>`），配色要等插件异步加载后才应用。② **时序根因**：内置配色的变量只定义在 `styles.css`（经 `app-plugins.js` 用 `fetch()` **异步注入**，且代码顺序在插件 js 执行**之后**）。启动时 head 前置把内置配色内联到 `<html>` 使首帧正确，但插件 `restore`→`applyTheme` 会 `clearCustomVars` **清掉这些 head 前置变量**，此时内置配色只能靠尚未就绪的 `styles.css` → 瞬间落回宿主 `html.dark/light` 默认色（闪深/闪浅）→ 待 `styles.css` 加载完再闪回配色。
- **状态**: 已修复（测试完成）
- **处理方法**: ① 配色应用目标统一为 `document.documentElement`（插件 `applyTheme` class、`applyBuiltinVars`/`applyCustomVars`/`clearCustomVars` 内联均挂 `<html>`），与首屏前置恢复同一元素、可正确清理不残留。② 新增共享主题数据源 `js/theme-palettes.js`（挂 `window.SB_PALETTES`：4 套内置配色 `BUILTIN`、`CUSTOM_VAR_PROPS`、`CUSTOM_FIELDS`、`buildCustomVars`/`readCustomColors`），`index.html` head 在 CSS 之前**同步**引用；首屏脚本据此内联内置/自定义配色，插件 `applyTheme` 对内置配色也调 `applyBuiltinVars()` 内联全套变量——内置配色不再依赖异步 `styles.css` 的加载时机，restore 清掉旧变量后同 tick 重内联，不再闪宿主默认色。③ 删除「停用」配色档：悬浮列表 `itemHTML('0','停用')`、循环 `colorOrder` 的 `'0'`、动作表 `disable`、manifest `defaultTheme` 的「停用」选项（默认改「纸白」）；`applyTheme(0)` 仅保留为「切宿主明暗档自动停配色」的内部行为。
- **验证结果**: 冒烟测试更新（删除停用项断言、配色改挂 `<html>`、cycle 顺序去除停用档）通过；回归新增 Bug-043 静态门禁（首屏 minimal 恢复与 theme-palettes.js 均在 CSS 之前、配色挂 `documentElement` 而非 `body`、悬浮无停用项、manifest 无停用默认纸白、插件内置配色走 `SB.BUILTIN` 内联、编辑器 fallback 按 minimal 配色编辑器深浅推导），`npm test` 84 通过、0 失败。
- **防再犯要点**: ① 首屏「渲染前恢复主题」须覆盖**所有主题维度**（宿主明暗 + 插件配色），前置到 head 且挂在**同一元素（`<html>`）**；② 任何配色的变量取值应落在**宿主同步资源**（如共享 `SB_PALETTES`）并在 head 同步引用，**不得依赖插件异步注入的样式文件**，否则会因 styles.css 晚于插件 js 执行而产生「清变量→样式未就绪→闪默认色」的时序闪烁（CD-29 新增）。
