# Bug-041 · 设置改为浅色（或「跟随系统」且系统为浅色）后，打开/重启应用的前几秒先显示深色，随后才跳成浅色。

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-041
- **日期**: 2026-09-10
- **现象**: 设置改为浅色（或「跟随系统」且系统为浅色）后，打开/重启应用的前几秒先显示深色，随后才跳成浅色。
- **复现地点**: `main.js`（主进程 `BrowserWindow` 创建，窗口层）+ `index.html`（`<html>` 首屏渲染，HTML 层）
- **原因**: 双层叠加。① HTML 层：`<html data-theme="dark">` 硬编码深色且无首屏同步主题脚本，首帧即按深色渲染，保存的浅色 `note-app:theme` 要到 `window.load` 后才由 `setTheme` 应用。② 主进程窗口层（修复 HTML 后仍闪的根因）：`createWindow` 未设 `show:false`，窗口一创建即用 `backgroundColor:'#1E1E2E'`（深色）填充显示，抢在页面浅色 `body` 渲染完成前露出深色画面——此层 HTML 首屏脚本无法干预，故先前仅修 HTML 仍失效。
- **状态**: 已修复（测试完成）
- **处理方法**: ① `index.html` 移除 `<html>` 硬编码 `data-theme="dark"`，在 `head` 的 CSS 引用**之前**插入同步脚本，按 `localStorage['note-app:theme']` 预置 `<html>` class（light/dark）与 `data-theme`/`data-theme-mode`；`auto` 时按 `matchMedia(prefers-color-scheme)` 判定实际明暗。② `main.js` 窗口 `show:false`，用 `ready-to-show` 事件在首帧渲染完成后再 `show()`，并加 4s 超时兜底强制显示（防渲染异常白窗/黑屏卡死，首帧完成即取消兜底）。
- **验证结果**: 回归静态门禁新增主进程断言（`main.js` 含 `show:false`、含 `ready-to-show`、含 `isVisible`+`setTimeout` 兜底），连同原有 HTML 断言共 6 条 Bug-041 门禁全部通过，`npm test` 77 通过、0 失败。
- **防再犯要点**: ① 首帧同步主题脚本须放 `head` 且**早于**外链 CSS，避免靠异步 `load` 恢复造成首屏明暗闪烁；`<html>` 不得硬编码与用户设置冲突的主题属性。②调整窗口外观/主题时，主进程 `BrowserWindow` 必须 `show:false` + `ready-to-show` 后再显示，避免窗口层深色背景抢在页面之前露出（CD-28 补充主进程层约束）。
