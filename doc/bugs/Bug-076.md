# Bug-076 · 重新打开知识库（无任何编辑）recent.json 每次被重写

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-076
- **日期**: 2026-10-15
- **现象**: 用户重新打开知识库、未做任何修改，`.second-brain/` 下文件被更新：① `recent.json` 每次打开都被重写（内容完全相同，仅 mtime 刷新）；② 新版首次打开库时全部 `_meta.json` 重写一遍（用户怀疑增量机制未生效）。库位于百度同步盘，无意义重写会触发同步盘误传输。
- **复现地点**: `second-brain/main.js`（IPC `notes:recentSave`）、`second-brain/js/editor/editor-host.js`（`openNote`→`persistRecentTabs`）、`second-brain/meta-vault.js`（`writeIfChanged` 新增）。
- **关联会话**: ED-33/ED-35 元数据增量维护改造交付后，用户真机（加密库 `D:\BaiduSyncdisk\my\second-brain\dfzx`）复验时发现。
- **原因**:
  1. **recent.json（真缺陷）**：`openNote` 每次打开/切换笔记都调 `persistRecentTabs()`（启动恢复最后一个标签页也会触发），主进程 `notes:recentSave` 直接 `mkdir + writeFile`，**没有与磁盘现状比对**——即使 tabs/pinned 内容一字不差也无条件落盘，mtime 每开必刷。
  2. **_meta.json（非缺陷，一次性收敛）**：首次以新版打开旧库时，镜像需补写新增的 `fh` 内容指纹字段（全目录写一次）；同时加密库笔记中残留的历史 frontmatter `id:` 被 `stripMetaId` 清理并加密重写，文件 `size` 变化导致次轮打开再收敛写一次。用真实库连续两轮真机快照（hash + mtime 全量对比）证实：**第二轮起 7 个 `_meta.json` 全部零写入、mtime 不变**，diff 机制正常。
- **状态**: 已修复（测试完成）
- **处理方法**:
  1. `meta-vault.js` 新增并导出通用最小化写入方法 `writeIfChanged(absPath, content)`：先读磁盘旧内容严格比对，相同返回 false 且不动文件（mtime 不变），不存在/不同才 mkdir+writeFile 并返回 true。
  2. `main.js` 的 `notes:recentSave` 改为 `await vaultMeta.writeIfChanged(recentMetaFile(), JSON.stringify({ tabs, pinned }, null, 2))`；旧版纯数组格式因与新序列化串不同，会正常升级写一次后稳定。
  3. 渲染端不改（仍可高频调用，幂等由主进程统一保证）。
- **验证结果**: `npm test` 280 通过、0 失败（新增 Bug-076-1~5：writeIfChanged 不存在创建/相同返回 false/mtime 不变/不同才写四条行为断言 + main.js recentSave 走 writeIfChanged 源码防回退断言）；真机 dfzx 加密库连续启动三轮：修复前 recent.json 每轮 mtime 刷新（11:01→11:11→11:13），修复后第三轮 mtime 精确保持 `11:13:18.5926398` 不变，同轮 7 个 `_meta.json` hash 零变化。
- **防再犯要点**: 见 `doc/bugs/防再犯清单.md` CD-57。
