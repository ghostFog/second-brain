# Bug-059 · 知识库单库多窗口（默认库每次触发都新开窗口）

> [返回 Bug 索引](../历史Bug记录.md) ｜ 状态：已修复（测试完成）

- **ID**: Bug-059
- **日期**: 2026-09-15
- **现象**: 一个知识库只能开一个窗口（G-13 单库单窗口），但触发「打开/切换/恢复默认库」时会**每次新开一个窗口**，而不是聚焦已有窗口。
- **复现地点**: `second-brain/main.js`（`createWindow` 的窗口去重分支）
- **原因**: `createWindow` 里窗口去重检查写在 `if (binding) { ... }` 内，仅对**非默认库**生效。而默认库统一被规范化为 `binding = null`，直接跳过该分支，因此对默认库从不执行「是否已有窗口」的检查，每次都 new 一个新 `BrowserWindow`。
- **状态**: 已修复（测试完成）
- **处理方法**: 去掉 `if (binding)` 条件，把去重检查提取到统一流程：无论默认库（`binding=null`）还是命名库都计算统一的库 key（默认库用 `vaultKey(binding || defaultVaultRoot())`，与 `syncVaultWinMap` 的登记口径 `vaultKey(vp || defaultVaultRoot())` 一致），命中已有窗口则聚焦、返回 null。
- **验证结果**: `node --check` 语法通过；`npm test` 163 通过、0 失败；手动待验证：重复触发「恢复默认库」只出现一个默认库窗口并聚焦。
- **防再犯要点**: 任何「按实体归一后以 `null` 代表默认态」的去重/归一逻辑（如默认库 `binding=null`），其**去重检查必须覆盖 null 默认态**，不得把检查写在 `if (binding)` / `if (p)` 等仅覆盖「有值分支」的守卫内；默认态应转换为与登记表一致的非空 key（`vaultKey(binding || defaultVaultRoot())`）后再查重（CD-44 已同类，本条为窗口侧补充：CD-46 新增）。
