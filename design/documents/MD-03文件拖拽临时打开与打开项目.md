## 一、MD-03：文件拖拽临时打开

### 1. 主进程（main.js + preload.js）
- 新增只读桥接 `notes:readFileExternal`：入参 `{ absPath }`，`fs.readFile`（限制大小，如 ≤5MB，避免内存/性能问题），返回 `{ path, name, content, binary }`；`binary` 由 null 字节检测。**不写任何盘、不建索引**。
- 新增 `notes:revealExternal`（可选）：临时文件右键「在资源管理器显示」。
- preload 暴露 `readFileExternal(absPath)`、`revealExternal(absPath)`。

### 2. 渲染进程（editor-filetree.js / editor-host.js / app-core.js）
- **窗口级外部拖拽**：在初始化处（`app-core.js` 一类入口）给 `window`/`document` 挂 `dragover`+`drop`（`capture` 阶段）。判断 `e.dataTransfer.files` 存在、非空、且**非** `#file-tree` 内部拖拽（内部拖拽无 `files`）。`preventDefault` 阻止浏览器默认打开文件导航。
- 用 `e.dataTransfer.files` 拿 `File`，经 preload 的 `webUtils.getPathForFile` 取真实绝对路径（Electron 安全）→ 调 `readFileExternal` 读内容。
- **临时文件区**：在 `#file-tree` 顶部渲染一个折叠区「临时文件」（复用 `collapsedFolders` 记忆折叠态）。每次打开新临时文件即**展开并聚焦**该区；临时文件行：文件图标 + 文件名 + 关闭(×)，单击重新读取内容打开，×移除（仅移除列表，不动磁盘）。当前无临时文件时区头仍显示但内容为空/「空」。
- **临时文件打开链路**：
  - 复用编辑区渲染（vditor `renderArticle` 系），但用一个合成路径 `temp://<name>` 与独立 `tempFiles` 映射存内容；
  - **标记模式**：打开/切换临时文件时置 `isTempMode=true`，**跳过** `renderFileProps`/`renderChunkPanel`/反链/侧边栏刷新（对应「侧边面板不更新」）；
  - 进入临时文件时**聚焦到临时文件区**（文件树滚动到该区 / 展开）。
- **不落库**：临时文件不进 `edNotes`、不进 `edOpenTabs`（知识库标签体系），仅独立临时状态；不触发任何 `refreshMeta`/`notes:list`。

### 3. 需求/进度文档登记（按项目规则）
- `doc/需求/需求-插件-MarkdownEditor.md` MD-03 状态推进（计划→编码→开发完成，细化落点）。
- `doc/开发进度.md` 看板 MD-03 行更新 + 完成后归档到 `doc/进度/进度-插件-MarkdownEditor.md`。

## 二、新增「打开项目」（非知识库工作区）

### 1. 主进程（main.js + preload.js）
- **窗口模式**：新增 `winProjects: Map<wcId, { path }>` 标记项目窗口。`createWindow` 增加可选 `{ project }` 参数；项目模式标题 `第二脑 · 项目：<basename>`；加载 `note://local/index.html?project=<abs>`。
- **项目目录选择器** `project:choose`：`dialog.showOpenDialog`（`openDirectory`）选目录 → 返回 `{ canceled, path, name }`（不强校验 git，用户所说「git」指该项目通常为 git 仓库，非必配）。
- **项目文件树/读写桥接**（全部收口到项目根，禁止越权）：
  - `project:list`：递归遍历项目根（跳过 `.git`、以 `.` 开头的目录按需隐藏），返回 `[{rel, name, folder, size, mtime, isBinary}]`（**含全部文本类型文件**，不只 `.md`）。
  - `project:read`：入参项目相对路径，读内容（`isBinary` 检测），限 ≤5MB。
  - `project:save`：写回相对路径（白名单后缀或大小上限保护，防写 `../` 越界——路径归一后必须以项目根开头）。
  - `project:gitStatus`：复用 git 白名单，但 cwd=项目根（新增 `projectGitRun`，与既有 `git:run` 分离，`GIT_ALLOWED_SUBCMDS` 复用，`status --porcelain` 解析出 增/改/未跟踪 着色 map）。
- **托盘**：`refreshTrayMenu` 增加「项目」分组：列出已打开的项目窗口（`winProjects`），点击聚焦/新开；尾部加「打开项目…」项 → `project:choose` 后 `openVaultWindow`-style 打开项目窗口。
- **库下拉**：`onVaultAction` 增加 `open-project` 分支，调 `chooseProject`（前面前端桥接）。

### 2. 渲染进程
- **项目模式分支**：`#init` 时按 `?project=`（或 `vault:get` 扩展返回 `type:`）判定 `isProjectMode()`。项目模式下：
  - 不走 `notes:list`/`noteStore` 初始索引加载；改用 `project:list` 渲染文件树（复用 `renderFileTree` 的嵌套/折叠逻辑，但由 `project:list` 数据驱动）。
  - 点击项目文件 → `project:read` 读内容 → 打开进编辑区（复用 `renderArticle`，合成路径 `project://<rel>`），保存走 `project:save`。
  - 侧边栏属性/反链/图谱/IPC 等知识库专属面板在项目模式**禁用或隐藏**（不建索引），仅保留可编辑的编辑区。
  - 文件树用 `project:gitStatus` 结果对行着色（复用现有 `window.__gsColoring` 与 `gs-*` class 机制）。
- 新增 `js/project/project-mode.js`：封装项目文件树渲染、打开/保存、git 状态拉取，暴露到 `window.sbProject`。
- `vault.html`：项目模式时隐藏知识库专属 UI（库统计/侧边面板等），或加一个简化的项目工作区布局容器。

### 3. 文档登记
- `doc/需求/需求-平台规划.md`（或新建 `需求-项目.md`）登记新功能点（编号走 GIT- 或独立前缀，**新增前缀需登记到 开发进度.md 各模块最大编号表**）；`doc/开发进度.md` 看板新增一行。

1. `cd second-brain && npm test`：跑既有 regression（确保 233+ 断言不破坏）。
2. 桌面版真机验证（`npm start`）：
   - **MD-03**：拖一个 `.txt`/`.md` 到窗口 → 打开为临时文件、文件树临时区出现并聚焦；夹显示/折叠正常；侧边面板不随临时文件变化；点 × 移除不复位磁盘；拖入多文件可切换。
   - **打开项目**：库下拉点「打开项目…」选中某 git 仓库目录 → 新窗口打开；文件树列出项目全部文本文件；打开任意文件可编辑保存；git 状态（改/未跟踪）着色正确；托盘出现该项目分组项与「打开项目…」入口；项目窗口不产生 `.second-brain`/索引副作用。
   - 无侵入回退：正常知识库窗口操作不受影响（笔记本渲染/标签/侧边栏/索引正常）。
3. 按回归规则为可确定性复现的部分在 `regression.test.js` 补断言（节点存在/模式切换/图片未引入的 DOM 断言为主）。
4. 提交前 `npm test` 通过（诊断脚本删、回归脚本保留）。

## 五、范围与取舍（避免过度设计）

- 项目模式为**轻量工作区**：可浏览/编辑文本 + git 状态着色，**不实现**完整 IDE（无断点/编译/多游标）。
- 新功能此前端与主进程仅做**模式分流**，不改动既有知识库渲染主干逻辑，确保已测功能回归无破坏。
- 「临时文件」与「项目工作区」两条链路相互独立、彼此不触发知识库索引。
