# 编辑界面：拖拽分流 · 临时文件可写 · 目录区新增笔记 · 命名调整

## Context

当前 second-brain 桌面的临时文件能力（`js/project-mode.js` 的 `sbTempFiles`）存在几个问题：
- 外部 md/txt 拖入窗口任意非 vditor 区域都会作为**临时文件只读打开**，且一律显示"复制"拖拽图标；
- 临时文件**只读、不可保存**（`sbSave` 对 `temp://` 伪路径 `return true` 直接忽略）；
- 文件树顶部会渲染一个"临时文件"区（图1红箭头），违背"目录区应只显示知识库笔记"的预期；
- 库下拉"最近打开"被特意置灰，与其他项（如"打开项目…"）颜色不一致；
- 界面入口把这套编辑视图统一叫"知识库"，与"打开项目"工作区（也是同一套编辑器界面）产生歧义。

**目标**（用户澄清后）：
- 拖到 **tab 栏** → 临时打开该 md/txt，且**支持编辑保存**（临时文件单独一套读写机制，直接写回原绝对路径）；
- 拖到 **目录区**（目录行 / 文件行 / 空白）→ 在**对应目录下新增一篇笔记并落盘**（走统一 `noteStore` 逻辑）；
- 目录区不再显示"临时文件"区块；
- 库下拉"最近打开"颜色与其它动作项一致，不特意置灰；
- 界面命名"知识库 → 编辑界面"（含文档中对该界面的称呼；保留模块名"知识库"与"知识库助手/知识库索引"等语义概念）。

## 现状关键代码（只读 / 桥接）

- 临时文件只读桥接：`main.js` `notes:readFileExternal`；preload 暴露 `readFileExternal` / `getPathForFile` / `revealExternal`。**暂无写回任意绝对路径的 IPC**。
- 临时文件保存拦截：`project-mode.js` `sbSave`（temp:// 返回 true）、`editor-host.js` `onEdInput` 的 `sbIsPseudoPath(p)` 分支。
- tab 栏外部文件 drop 分发：`editor-host.js` `initEditor` 内 `tabs.addEventListener('drop')`（已实现 openTemp）。
- 目录区内部拖拽：`editor-filetree.js` `bindFileTreeDrag` / `handleFileTreeDrop` / `doNewNote`。
- 临时区渲染进文件树：`editor-filetree.js` `renderFileTree` 末尾 `sbRenderTempArea(tree)`；来源 `project-mode.js` `renderInto/areaHtml`。
- 库下拉：`app-vault.js` `最近打开` head（`color:var(--note-ink-3)` 置灰）。
- 入口命名：`app-core.js` `ROUTES.editor.name='知识库'`；`app-ribbon.js` `BUILTIN_BUTTONS` editor `title:'知识库'`。
- 目录区新增新建笔记的落盘样板：`doNewNote`（`noteStore.create(name, dir)` → `noteStore.save` → 刷新 `edNotes`/`renderFileTree`）。

## 实施步骤

### 1. 临时文件支持写回（可编辑保存）
- `main.js`：新增 IPC `notes:writeFileExternal`（`{absPath, content}` → 直接写回 UTF-8），与 `readFileExternal` 对称；仅接受已登记 temp 记录中的绝对路径做白名单校验，控制风险。
- `preload.js`：`noteDesktop` 暴露 `writeFileExternal(absPath, content)`。
- `project-mode.js` `sbSave`：对 `temp://` 伪路径，从 `path.slice('temp://'.length)` 取出绝对路径 → 调 `writeFileExternal` 写回 → 返回 `true`。
- `editor-host.js` `onEdInput` 的 `sbIsPseudoPath(p)` 分支：不再显示"只读"，改为走 `sbSave` 写回（与知识库一致的自动保存流程）。

### 2. Tab 栏拖拽临时打开（保留 + 不显示"复制"）
- 保留 `editor-host.js` tab drop 打开临时文件逻辑。
- 全局 `dragover`（`project-mode.js bindGlobalDrag`）不再一律 `dropEffect='copy'`：tab 栏拖入临时文件时显示"打开/移动"，不显示"复制"。（按落点分流后，目录区拖入由文件树新增笔记逻辑接管，全局不再拦截临时打开。）

### 3. 目录区拖入新增笔记（按落点落盘）
- `editor-filetree.js` `bindFileTreeDrag`：
  - drop 时判断 `dragSrc` 为空但 `dataTransfer.files` 非空 → 进入"外部文件新增笔记"分支；
  - 落点目录：drop 在 `.tree-folder` → 该目录；`.tree-file` → 其父目录；空白 → 根目录；
  - 读外部文件内容（`nd.getPathForFile` + `nd.readFileExternal`）→ 复用类 `doNewNote` 逻辑：`noteStore.create(name, dir)` → `noteStore.save(rel, content)` → 刷新 `edNotes`/`renderFileTree`/`persistRecentTabs`/`refreshTreeAfterChange`。

### 4. 目录区不再显示"临时文件"区
- `editor-fileteee.js` `renderFileTree` 末尾删除 `sbRenderTempArea(tree)` 调用；
- `project-mode.js` `renderInto`/`areaHtml` 不再被调用（保留 `openTemp/closeTemp/recordRecent/renderTempTab` 等能力，供 tab 栏与库下拉"最近打开"继续使用）；
- 同步清理 `editor-host.js` 顶部空实现 shim `sbRenderTempArea`（保留空实现防断链即可）。

### 5. 库下拉"最近打开"去置灰
- `app-vault.js`：`最近打开` 分组 head 的图标与文字去掉 `color:var(--note-ink-3)` 特意置灰，与"打开项目…"等动作项颜色一致。

### 6. 界面命名"知识库 → 编辑界面"
- `app-core.js`：`ROUTES.editor.name` `'知识库'` → `'编辑界面'`；
- `app-ribbon.js`：editor 按钮 `title` `'知识库'` → `'编辑界面'`；
- 文档同步：`doc/需求/需求-编辑界面.md`、`doc/设计/设计-编辑界面.md`、`doc/开发进度.md` 等中**指代此编辑界面**的"知识库" → "编辑界面"；保留模块名"知识库"、`ED-` 编号、以及"知识库助手/知识库索引/知识库内 .second-brain 目录"等语义不算界面名称，不改。
- `doc/需求/需求-编辑界面.md` 新增功能点条目（拖拽分流 / 临时可写 / 目录区无临时区已有 ED-33/44 相关，新增编号）并登记到 `doc/开发进度.md` 看板（状态=计划，随实现推进到完成再归档）。

## 验证

1. 启动：`cd second-brain && npm start`（或双击 `start-desktop.bat`）。
2. Tab 栏拖入：把一个外部 `.md`/`.txt` 拖到 tab 栏 → 打开且**可编辑**；修改后失焦等待自动保存 → 用系统编辑器打开原文件确认已写回；拖拽过程中不显示"复制"。
3. 目录区拖入：把外部 `.md` 拖到某目录行 → 该目录新增一篇笔记（内容为原文件内容）；拖到文件名 → 同级目录新增；拖到空白 → 根目录新增；`npm test` 回归通过。
4. 目录区：不再出现"临时文件"区块。
5. 库下拉：点标题栏库选择器 → "最近打开"分组文字颜色与"打开项目…"一致。
6. 界面入口：Ribbon 编辑按钮 title 与路由文档标题显示"编辑界面"。
7. `npm test`（`node regression.test.js`）通过；如可复现 bug 补回归断言。
