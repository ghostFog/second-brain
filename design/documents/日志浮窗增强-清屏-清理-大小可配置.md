# 日志浮窗增强：清屏 / 清理 / 单文件大小可配置

> 关联功能：G-18（Git 失败日志与日志目录可配置）
> 作者：火 冰

## 一、需求

在既有「日志查看独立浮窗」（`logview.html`，`app.openLogViewer` 打开）与设置页「常规-其他」日志配置基础上，新增三项能力：

1. **清屏**（浮窗内按钮）：只清除**界面上的日志显示**，不清文件、不持久化；清完后实时模式继续从当前点接收新日志。
2. **清理**（浮窗内按钮）：**清空日志文件本身**（清空 `app.log` 与 `error.log` 内容），并同步清屏。
3. **单日志文件大小可配置 + 自动拆分**：主进程现以常量 `LOG_MAX_BYTES = 5MB` 轮换；改为用户可配置大小（MB），超限自动轮换拆分仍照旧（当前文件 → `.1`）。

## 二、设计

### 主进程（main.js）
- 常量 `LOG_MAX_BYTES` 改为可配置变量 `logMaxMB`（默认 5，单位 MB）；`writeLogLine` 判断阈值改为 `logMaxMB * 1024 * 1024`。
- `loadConfig/saveConfig` 增加 `logMaxMB` 字段持久化（settings.json）。
- 新增 IPC：
  - `app:getLogMaxMB` → 返回当前单文件上限（MB，整数）。
  - `app:setLogMaxMB (mb)` → 校验为正数后保存并持久化，返回新值。
  - `app:clearLogFile (type)` → 把 `app.log` / `error.log`（按 type）清空（写空串）。
- `app:readLog` 不变。

### 渲染端浮窗（logview.html）
- 标题栏按钮区新增两个按钮：**清屏**（`data-act="clear-screen"`）、**清理**（`data-act="clear-file"`）。
  - 清屏：`#lgbody` 文本清空；若实时未开，保持空。
  - 清理：`nd.clearLogFile(logType)` → 成功后清空界面并刷新。
- 逻辑复用 `refreshLog`。

### Preload（preload.js）
- 暴露 `getLogMaxMB` / `setLogMaxMB` / `clearLogFile`。

### 设置页（settings-panels.js / settings-core.js / settings-plugins.js）
- 「常规-其他」日志配置区块：在「运行日志目录」输入框组下新增一行「单文件大小(MB)」输入框（内联可编辑）+「保存」；`bindLogDir` 回填当前 `getLogMaxMB`；`bindActionButtons` 新增 `set-logmax` 分支写回主进程并提示。
- 清理是浮窗按钮，不需设置页按钮。

## 三、边界
- 清屏/清理只在独立浮窗提供；设置页的「查看」仍打开该浮窗。
- `app:clearLogFile` 仅清空内容，不删除文件本身、不删除 `.1` 拆分历史（保持幂等、可追加）。
- 拆分轮换逻辑与现有一致，仅阈值从常量变为可配置。

## 四、验证
- `node --check` 语法检查；`npm test` 回归不破坏既有 240 用例。
- 真机确认：清屏不删文件、清理清空文件、大小配小后写入超限自动拆分 `.1`。
