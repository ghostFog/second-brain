# 计划：插件命令注册 + 设置快捷键

## Context（背景与目标）

当前「第二脑」的快捷键是**硬编码**在 [app-layout.js](file:///d:/project/aiCode/second-brain/second-brain/js/app-layout.js) 的全局 `keydown` 里（Ctrl+P/G/N/F/R、Esc、方向键、Enter），无法配置；设置页「快捷键」分类也只是展示一段写死的列表，「恢复默认」仅弹 Toast，命令面板里的 `shortcut` 是写死文案。插件命令虽然能进命令面板（PL-12），但**无法绑定快捷键**。

需求：插件能**声明哪些功能支持快捷键及默认快捷键**，启动插件时自动注册、停用时卸载；若默认快捷键与已有绑定冲突则不自动生效。同时「内置 + 插件命令」都可在**设置-快捷键**里重绑。

## 方案总览

新增一个**快捷键命令注册表**模块 `app-keybinds.js`：统一登记「内置命令 + 插件命令」，每个命令带稳定 `id`、可选默认快捷键、可选 `keybindable` 开关、执行函数。全局 `keydown` 改为查注册表匹配并执行；设置页快捷键列表改为动态渲染 + 捕获重绑 + 恢复默认；命令面板展示的快捷键来自注册表。内置命令的默认键迁移进注册表，保证行为不变。

## 实施步骤

### Phase A — 新增 `js/app-keybinds.js`（核心注册表）
作者: 火 冰。导出到 window（`globalThis.keybinds` 或全局函数），提供：
- 命令定义 Map：`{ id, label, icon, group, action, defaultShortcut?, keybindable?, pluginId?, when? }`
- 组合键 Map：`normalizedCombo -> commandId`（用于冲突检测与匹配）
- `kbRegisterCommand(cmd)`：加入定义表；若 `cmd.defaultShortcut` 且该组合未被占用（`kbCanClaim`），才写入组合键映射；占用则仅登记命令、快捷键留空。
- `kbUnregister(id)` / `kbUnregisterPlugin(pluginId)`：移除命令并释放其组合键（停用/卸载插件时调用）。
- `kbSetBind(id, combo)`：用户重绑。验证 combo 非空、不与其它命令冲突（冲突返回 `{ok:false, conflictId}`）；成功则写入组合键映射 + `saveS('keybind:'+id, combo)`。
- `kbClearBind(id)`：清除用户绑定（恢复遵循默认或为未设置），删除 `keybind:*`。
- `kbGetBinds()`：返回全部命令 `[{id,label,group,icon,combo,keybindable,pluginId}]`，`combo` 取值优先级：用户绑定 > 默认快捷键 > ''。
- `kbResolveBind(id)`：仅默认值（供 icon 展示当前生效键的兜底）。
- `kbMatch(e)`：把事件归一化为组合串（Mod=Ctrl/Meta、Alt、Shift + 主键），查组合键映射返回命令；带 `when`（如 `activeView==='editor'`）的命令额外校验。
- 内置默认命令表（含现有硬编码键，保证行为不变）：
  - 打开命令面板 `Ctrl+P`（when 无）
  - 新建笔记 `Ctrl+N`
  - 打开图谱视图 `Ctrl+G`
  - 打开设置 / 打开 AI 问答 / 浏览插件市场 / 切换主题 / 同步设置 / 导出为 PDF（无默认键，但可绑定）
  - 编辑器查找 `Ctrl+F`（when `activeView==='editor'`）/ 查找替换 `Ctrl+R`（when 编辑器）
- 启动构建：注册内置命令后，读取 `pluginManager.getCommands()` 把插件命令一并登记（含各自 defaultShortcut/keybindable）。

### Phase B — 插件命令可声明快捷键 + 生命周期联动：`js/app-plugins.js`
- manifest `commands[]` 元素扩展可选字段：`shortcut`（默认快捷键，如 `"Ctrl+K"`）、`keybindable`（默认 true）。
- `materializePlugin`：命令映射函数时透传 `shortcut`/`keybindable`，并给命令注入稳定 `id` = `pluginId + ':' + actionKey`。
- `pluginManager.getCommands()` 返回项补 `id`/`shortcut`/`keybindable`。
- 注册/停用/卸载挂钩（调用 keybinds 同步，避免循环依赖）：
  - `install()` 末尾 → `kbRegisterPluginCommands(pluginId)`（遍历该插件命令登记，默认键仅在无冲突时占用）。
  - `uninstall()` / `setPluginEnabled(false)` → `kbUnregisterPlugin(pluginId)`。
- `PluginAPI.registerCommand({id,label,icon,group?,shortcut?,keybindable?,action})`：运行时动态注册命令并同步进注册表（供插件 main.js 使用，错误边界包裹）。
- 注意加载顺序：`app-keybinds.js` 需在 `app-plugins.js` 之后加载（index.html），但 keybind 对 pluginManager 的访问仅在函数内做 `typeof` 守卫。

### Phase C — 全局 keydown 改走注册表：`js/app-layout.js`
- 移除硬编码的 Ctrl+P/G/N/F/R 命令分支，改为：先处理命令面板 UI 键（Esc 关闭、方向键/Enter 导航，保留），其余交给 `kbMatch(e)`：
  - 命中命令 → `e.preventDefault()` + 执行 `cmd.action()`（命令面板相关命令自行 `closePalette()`）。
  - 未命中 → 保持现状（编辑器查找条仍由「查找/查找替换」命令承载）。
- 输入态防护：当焦点在 `input/textarea/[contenteditable]` 且非命令面板时，不触发命令（避免打字误触发），但 Ctrl+P 等旗舰命令可保留（命令面板也用它打开）。

### Phase D — 设置-快捷键 动态配置面板：`js/app-settings.js`
- 「快捷键」分类改为：先渲染「内置」组合键说明，再遍历 `kbGetBinds()` 列出全部命令（内置+插件）。
- 每行列：命令名 + 插件来源徽标 + 当前快捷键 `<kbd>` + 「设置」按钮 + 「清除」按钮。
- 设置按钮：点击进入捕获态（按钮文案切换为“按下组合键…”，监听 keydown 一次）→ `kbSetBind`；冲突时 Toast 提示“快捷键已被其它命令占用”。
- 清除按钮：`kbClearBind`。
- 「恢复默认」：遍历删除所有 `keybind:*` 存储项并重建注册表（回到内置默认），刷新列表 + 命令面板。
- 复用 `saveS/restoreS`（存 `keybind:<id>`）、`bindActionButtons`（data-saction 分支）。

### Phase E — 命令面板展示生效快捷键：`js/app-core.js`
- `renderPalette`/`buildCommandList` 里 `shortcut` 取值改为查 `kbResolveBind(id)`（用户绑定 > 默认），移除写死的 `'⌘N'` 等文案（改为注册表驱动）；无快捷键不显示 kbd。
- 内置命令项补 `id` 便于查询绑定。

### Phase F — 收尾：校验 / 测试 / 文档
- `node --check`：app-keybinds.js / app-plugins.js / app-layout.js / app-settings.js / app-core.js。
- 新增或扩展 `smoke-keybind.test.js`（jsdom）断言：
  - 注册内置命令 + 插件命令，默认键无冲突生效、冲突不强占。
  - `kbSetBind` 重绑、`kbClearBind` 清除、`kbUnregisterPlugin` 停用即释放。
  - 设置「快捷键」面板渲染出命令行并可捕获。
- 更新 `doc/开发进度.md`（新增跟踪行）与 `doc/功能需求文档.md`（登记 PL-16 / 快捷键改造）。
