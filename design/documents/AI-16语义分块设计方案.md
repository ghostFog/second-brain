# AI-16 语义分块 设计方案

## Context（背景与目标）

需求 [需求-AI问答.md](file:///d:/project/aiCode/second-brain/doc/需求/需求-AI问答.md#L22) 中的 AI-16「语义分块」：索引支持按语义拆分块（按段落 / 标题层级 / 语义完整句切分），而非固定字符数硬切；设置页知识库索引提供切分策略（固定字符 / 语义分块），与现有块大小/重叠配置共存。

经与用户确认，补充三点要求：
1. **语义模式下忽略「相邻重叠」**；且每个语义块头部**注入上下文**——`文件名 + 当前所在标题`（若处在二级标题下，还需带上一级标题）。
2. **语义策略支持单笔记级覆盖**（复用现有 `note.chunk` 元数据覆盖机制）。
3. **记录每篇笔记的索引时间**；当索引时间早于笔记文件更新时间时，支持**手动重建单篇笔记索引**。

现状：分块逻辑集中在 [ai-engine.js](file:///d:/project/aiCode/second-brain/second-brain/ai-engine.js) 的 `chunkText / chunkConfigured`（固定字符 + 重叠硬切，仅回退到行换行）；索引持久化为 `{ vaultName, builtAt, chunks[{id,noteId,path,block,text,start,end,vec}] }`，无每篇索引时间；设置 UI 在 [settings-panels.js](file:///d:/project/aiCode/second-brain/second-brain/js/settings/settings-panels.js#L243-L256) 知识库索引区块；「查看索引」面板在 [editor-sidepanel.js](file:///d:/project/aiCode/second-brain/second-brain/js/editor/editor-sidepanel.js#L284-L325) 的 `renderIndexPanel`；「文件属性→索引分块」单笔记覆盖面板在 [editor-sidepanel.js](file:///d:/project/aiCode/second-brain/second-brain/js/editor/editor-sidepanel.js#L122-L200) 的 `renderChunkSection`。

## 改动清单

### A. 引擎层 `second-brain/ai-engine.js`

1. **`DEFAULT_CONFIG` 增加** `chunkStrategy: 'fixed'`（取值 `'fixed' | 'semantic'`，全局默认）。

2. **新增顶层纯函数 `semanticChunkText(text, opts)`**
   - `opts: { size, maxChunkSize, fileName }`（`size`=目标窗宽，`maxChunkSize`=块绝对上限封顶，**忽略 overlap**）。
   - 算法：按行扫描识别标题行（`^#{1,6}\s+`）维护「当前标题链」=最近一个一级标题 + 其下最近的二级标题（若存在，格式 `一级 / 二级`）；断点优先级 **标题行 > 空行（段落边界）> 句末符（。！？.!?；;）> 块大小兜底**。
   - 每个块文本 = `前缀(文件名 [+ 当前标题链]) + 语义正文`，保证检索块自包含上下文。
   - 返回 `[{ text, start, end }]`，`start/end` 为该块正文在原文的字符区间。

3. **扩展 `chunkConfigured` 尾参**：追加 `(strategy, fileName)`；当 `strategy === 'semantic'` 时走 `semanticChunkText`（`fileName` 传 `path.basename(rel)`），否则保持原固定分块。旧调用不传参仍为 fixed，向后兼容。

4. **`_chunkParamsFor` 返回 `strategy`**：全局 `cfg.chunkStrategy` 兜底；被 `note.chunk.strategy` 覆盖时用单笔记值（单笔记覆盖）。

5. **`rebuildIndex` / `updateNote`**：取出 `strategy` 并传入 `chunkConfigured`（`fileName=basename(path)`）；为新块保留 `start/end`。

6. **索引时间记录**：索引对象增加 `noteIndexAt: { [noteId]: ts }`；`rebuildIndex` 每篇写入、`updateNote` 刷新对应篇；`_saveIndex` / `_loadIndexFrom` 读写该字段（旧索引缺失时按 `builtAt` 兜底）。

7. **`listIndex` 返回过期判定数据**：每个 group 增加 `indexedAt`（该 noteId 的索引时间）与 `mtime`（`fs.statSync(path).mtimeMs`，读取失败为 `0`）。

8. **新增 `rebuildNoteIndex(rel)`**：手动强制重建单篇笔记索引（复用 `updateNote` 的重算/替换骨架，供「单篇过期重建」入口调用）。

### B. 主进程与预加载

9. **`main.js`**：
   - `ai:previewChunk` handler 追加透传 `strategy` 与 `fileName`（`path.basename(rel)`）两个尾参 → `chunkConfigured(text, size, overlap, offsets, maxChunkSize, strategy, fileName)`。
   - 新增 `ipcMain.handle('ai:rebuildNoteIndex', ...)` → `engine.rebuildNoteIndex(rel)`。

10. **`preload.js`**：`ai.previewChunk` 签名追加 `strategy`；新增暴露 `ai.rebuildNoteIndex = (rel) => ipcRenderer.invoke('ai:rebuildNoteIndex', rel)`。

### C. 设置层（全局切分策略）

11. **`js/settings/settings-panels.js` 知识库索引区块**（`maxChunkSize` 上方）：新增「切分策略」下拉 `data-ai-cfg="chunkStrategy"`，选项「固定字符 / 语义分块」；选语义分块时在区块内显示提示「语义分块按标题/段落/句末切分，忽略相邻重叠；单块上限仍生效」。
12. **`js/settings/settings-ai.js`**：`collectLocal / fillLocal` 已按 `el.value` 通用处理 `select`，无需改动；确认下拉初值回填正确。

### D. 编辑器（单篇过期重建 + 单篇覆盖）

13. **`renderIndexPanel`（查看索引面板，editor-sidepanel.js L284）**：用 `ai.listIndex()` 中找到当前 `edCurrent` 的 group；若 `indexedAt` 缺失或 `indexedAt < mtime`，在块列表顶部渲染「索引已过期」提示 + 「重建本篇索引」按钮 → 调用 `ai.rebuildNoteIndex(edCurrent)` → 完成后重新 `renderIndexPanel()`。
14. **`renderChunkSection`（文件属性→索引分块，editor-sidepanel.js L122）**：顶部「块大小/相邻重叠」旁新增「切分策略」下拉（fixed/semantic，初值取 `note.chunk.strategy` 或全局）；并入保存逻辑持久化到 `note.chunk.strategy`；`previewChunk` 调用透传 `st.strategy`。

### E. 文档同步（AGENTS 规则）

## 复用与不改动
- `collectLocal / fillLocal`（settings-ai.js）复用实现下拉收集/回填，不改。
- `updateNote` 增量逻辑作为 `rebuildNoteIndex` 骨架复用。
- 固定字符分块路径（`blockSize/overlap/offsets`）逻辑不变，仅尾参透传。
