# 多窗口知识库改造计划

## Context（背景）

**问题**：左上角「打开知识库 / 切换知识库」目前是**改主进程全局 `currentVault` + 当前窗口 `location.reload()`** 的单窗口模型。用户反馈：切换/打开后界面显示成新库名、但内容/状态与实际库不一致；且用户希望**每个知识库一个独立主窗口**，同库只能有一个窗口。

**目标**：
1. 打开/切换知识库 → **新开一个主窗口**显示新库，当前窗口保持不变。
2. 同一知识库已有一个窗口时 → **聚焦已有窗口**，不开新窗口（单库单窗口）。
3. 修复「显示成切换了、实际没切换」——改造后当前窗口永不切库，此问题根除。
4. 窗口标题带库名（如「第二脑 · 我的笔记库」），便于区分。
5. 窗口级生命周期：最小化只藏当前窗口；多窗口时关闭按钮只关当前窗口（最后一个窗口关闭才退出）。

**关键现状**（已探明）：
- `main.js`：单 `mainWin` 全局、全局 `currentVault`；`vaultRoot()` 返回 `currentVault || defaultVaultRoot()`；约 40 个 `ipcMain.handle` 内部直接调 `vaultRoot()`；`note://` 协议与 `aiEngine` 也依赖 `vaultRoot()`。
- 渲染端 `js/app-vault.js` `onVaultAction()`：switch/open/reset/migrate 成功后均 `window.location.reload()`。
- `vault:get` 的库名逻辑：`currentVault ? path.basename(p) : '我的笔记库'`。
- 关闭按钮行为：`closeAction ∈ ['confirm','quit','tray']`（默认 quit）+ 首次弹窗询问；设置页 `#close-action` 下拉三选项。
- Electron 33（Node 20+），支持 `AsyncLocalStorage`。

## 方案（核心思路）

**窗口绑定知识库 + 按窗口解析库根**：

1. 主进程维护 `winVaults: Map<webContentsId, 库根|null>`（null=跟随默认库），每个窗口创建时绑定自己的库。
2. 用 Node `AsyncLocalStorage` 包一层 `vaultHandle()` 替换所有 `ipcMain.handle`，在 IPC 请求链内把 `vaultRoot()` 解析为**发起窗口**的库根 → 内部函数（`resolveVaultPath`/`ensureVault`/`walkNotes`/`scanVaultMeta` 等约 20 处）与 `aiEngine` 的 `getVaultRoot()` **零改动**自动按窗口工作。
3. `vaultRoot()` 兜底改为 `activeVault || defaultVaultRoot()`（`activeVault` 随窗口 focus 更新），供 `note://vault_res` 协议等无窗口上下文使用。
4. 单库单窗口：`vaultWinId: Map<库key(小写路径), winId>` + `syncVaultWinMap()` 全量重建；`openVaultWindow(target)` 已有窗口则聚焦、否则 `createWindow(target)`。
5. 切换/打开/恢复库 IPC 改为「目标库 → openVaultWindow」，**不再改当前窗口**；渲染端去掉 reload。

## 改动文件

### 1. `second-brain/main.js`（核心）

**a. 顶部新增**（require 区 + 状态区）：
```js
const { AsyncLocalStorage } = require('node:async_hooks');
const vaultCtx = new AsyncLocalStorage();   // IPC 请求上下文：窗口 → 库根
const winVaults = new Map();                // webContentsId → 库根(null=默认库)
const vaultWinId = new Map();               // 库key(小写) → winId（单库单窗口）
let activeVault = null;                     // 最近聚焦窗口的库根(null=默认库)
```

**b. `vaultRoot()` 改造**：
```js
function vaultRoot() {
  const store = vaultCtx.getStore();
  if (store && store.root) return store.root;   // IPC 链内：按发起窗口解析
  return activeVault || defaultVaultRoot();     // 协议/无上下文：最近聚焦窗口
}
```

**c. 新增辅助函数**（放 `vaultRoot` 附近）：
- `winFromEvent(event)` → `BrowserWindow.fromWebContents(event.sender)`
- `windowVaultBinding(event)` → 窗口绑定值（null 或路径，供 `vault:get` 区分「我的笔记库」）
- `vaultRootForEvent(event)` → 绑定值转库根（null → `defaultVaultRoot()`）
- `vaultKey(root)` → `path.resolve(root).toLowerCase()`
- `syncVaultWinMap()` → 遍历 `winVaults` 重建 `vaultWinId`
- `openVaultWindow(target)` → 已有窗口 `showWindow`，否则 `createWindow(target)`
- `showWindow(w)` / `hideWindowToTray(w)`（原 `hideToTray` 逻辑改为按窗口）
- `vaultHandle(channel, fn)`：
  ```js
  function vaultHandle(channel, fn) {
    ipcMain.handle(channel, (event, ...args) =>
      vaultCtx.run({ root: vaultRootForEvent(event) }, () => fn(event, ...args)));
  }
  ```

**d. `createWindow(vaultPath)` 多窗口化**：
- 签名 `createWindow(vaultPath)`（undefined→跟随默认库；启动时默认 `currentVault`（loadConfig 恢复值，目录失效则 null））。
- `winVaults.set(win.webContents.id, 绑定值)` + `syncVaultWinMap()`。
- `loadURL('note://local/index.html' + (绑定值 ? '?vault=' + encodeURIComponent(绑定值) : ''))`（query 仅为信息性，渲染端仍走 `vault:get`）。
- 标题：`'第二脑'` 或 `'第二脑 · ' + (绑定值 ? path.basename(绑定值) : '我的笔记库')`。
- 现有事件监听（ready-to-show / 兜底显示 / before-input-event / did-finish-load / console-message / setWindowOpenHandler / will-navigate）中 `mainWin` 全部换成局部 `win`。
- 新增 `win.on('closed')`：清理 `winVaults`/`syncVaultWinMap`/`mainWin` 引用；`win.on('focus')`：`activeVault = winVaults.get(id) ?? null`。
- `mainWin = win` 保留（兼容引用，最近窗口）。

**e. 所有 `ipcMain.handle(` → `vaultHandle(`**（约 40 处机械替换；handler 签名不变，`_e` 参数继续有效）。`vaultRoot()` 在 handler 内自动按窗口解析，**内部业务代码不改**。

**f. `vault:*` IPC 语义改造**：
- `vault:get`：name 判断从 `currentVault ?` 改为 `windowVaultBinding(event) ? path.basename(...) : '我的笔记库'`。
- `vault:choose`：弹目录 → `recordHistory(vaultRoot())`（当前窗口库）+ `recordHistory(target)` + `saveConfig()` → `openVaultWindow(target)` → 返回 `{ canceled:false, opened:true }`（不再设 `currentVault`、不再改当前窗口）。`saveConfig` 里 `vaultPath` 持久化为新库（下次启动主窗口用它）。
- `vault:switch`：目录存在校验 → 同上 → `openVaultWindow(target)` → `{ canceled:false, opened:true }`。
- `vault:reset`：`recordHistory(vaultRoot())` + `saveConfig()` → `openVaultWindow(defaultVaultRoot())` → `{ canceled:false, opened:true }`。
- `vault:remove`：不变。
- `vault:migrate`：迁移成功后，**除发起窗口外**，遍历 `winVaults` 中绑定为 null（跟随默认库）或等于旧默认路径的窗口 → 改绑定为 null + `syncVaultWinMap()` + `win.webContents.reload()`；发起窗口保持不动（渲染端自己 reload + toast）。返回 `{ canceled:false, migrated:true }`。
- `recordHistory` 不改（接收显式路径）。

**g. 窗口控制 IPC（窗口级）**：
- `win:minimize` → `hideWindowToTray(winFromEvent(e))`（只藏当前窗口）。
- `win:maximize` / `win:fullscreen` / `win:devtools` → 操作 `winFromEvent(e)`。
- `win:close`：
  - 多窗口时（`getAllWindows` 未销毁数 > 1）：`closeAction==='quit'` → `app.quit()`；`closeAction==='tray'` → 藏当前窗口；否则 `win.close()`（销毁当前窗口）。
  - 单窗口时：保留现有 confirm/quit/tray + 首次弹窗逻辑（`mainWin` 换 `win`），不破坏已测试功能。
- dialog 父窗口（`vault:choose` / `vault:migrate` / `ai:pickModelDir` / `dialog:confirm`）：`mainWin` → `winFromEvent(event)`（或 `event.sender` 窗口）。

**h. 托盘**：
- `hideToTray()` → `hideWindowToTray` 仅用于单窗口兼容路径；`showMainWindow()` → 遍历 `getAllWindows()` 全部 `showWindow`，无窗口则 `createWindow()`。
- `second-instance` / macOS `activate` → `showMainWindow()`。
- `app.whenReady`：`createWindow()`（初始库 = loadConfig 恢复的 `currentVault`）。

**i. 协议与 AI 引擎**：`registerNoteProtocol` 的 `vault_res`、`initAiEngine` 的 `getVaultRoot` 均走 `vaultRoot()`（已感知 activeVault），**不改**。

**j. module.exports**：补充导出 `vaultRootForEvent / openVaultWindow / syncVaultWinMap / winFromEvent` 等纯逻辑（供单测），保留 `migrateDefaultVault` 等。

### 2. `second-brain/js/app-vault.js`（渲染端）

`onVaultAction()`：
- `switch`：去掉 `window.location.reload()`；`res.opened` 时仅关闭下拉框，`canceled` 保持 toast。
- `open` / `reset`：去掉 `window.location.reload()`。
- `migrate`：**保留**现有 reload + `sessionStorage.setItem('vaultMigrated','1')` 逻辑（主进程已处理其他窗口，发起窗口自己重载提示）。
- `initVaultPicker` 其余不变。

## 验证（Verification）

1. `npm test`（回归门禁，node regression.test.js）通过。
2. 手动 `npm start` 逐项验证：
   - 默认库窗口标题为「第二脑 · 我的笔记库」。
   - 「打开知识库…」选另一目录 → **新窗口**出现显示新库，原窗口不变。
   - 再打开同一库 → 聚焦已有窗口，不新开；同时窗口数不超库数。
   - 下拉历史库切换 → 新窗口/聚焦已有窗口。
   - 两个窗口分别新建/编辑笔记互不串库（A 窗口保存的笔记只在 A 库出现）。
   - 最小化其中一个窗口 → 仅该窗口藏托盘；托盘「显示主窗口」恢复全部。
   - 多窗口下关闭一个窗口 → 仅该窗口关闭；最后一个窗口关闭 → 程序退出。
   - 单窗口下关闭按钮行为（quit/tray/confirm/首次询问）与原逻辑一致。
   - 迁移默认知识库：发起窗口重载并提示，其他默认库窗口同步刷新为新默认库。
3. 完成开发后更新 `doc/开发进度.md` 状态与 `doc/进度/进度-全局框架.md` 归档（按「已完成归档规则」）。

## 风险与取舍

- `note://vault_res` 资源加载无窗口上下文，用 `activeVault`（最近聚焦窗口）兜底；多窗口下后台窗口加载图片属低频场景，可接受（同库单窗口约束下一般聚焦窗口即正确窗口）。
- `aiEngine` 全局单例，索引按库路径分文件；多窗口下 AI 操作跟随最近聚焦窗口，用户在哪个窗口操作即命中哪个库。
- 不破坏设置页「关闭按钮行为」三选项与已测试的回归断言。
