# 应用安全：启动密码与超时锁定

> 关联功能：SEC-01（启动密码）、SEC-02（超时锁定遮罩）
> 作者：火 冰

## 一、需求

为桌面版「第二脑」增加应用安全意识能力：

1. **启动密码（SEC-01）**：用户在「设置 → 隐私与安全 → 应用密码」自行开启。开启后，每次打开应用需输入密码才能进入主界面。
2. **超时锁定遮罩（SEC-02）**：应用长时间未操作（默认 10 分钟，可配置）后，弹出全屏遮罩，需重新输入密码才能继续使用；密码正确则移除遮罩恢复原界面。

决策口径（已确认）：

- **首次启动不强制设置密码**，首次直接进入主界面；密码由用户到设置页自行开启。
- **认证库使用 Node 内置 `crypto.scrypt`**（零新增依赖，避免 electron 打包原生模块负担）。

## 二、设计

### 2.1 密码存储与校验（主进程 main.js）

- 主进程维护安全状态：

  - `getSecurityFile()`：`path.join(app.getPath('userData'), 'security.json')`，与 `settings.json` 分离，避免配置与密钥混存。文件内容：`{ pwdHash, salt, lockEnabled, lockMinutes }`。
  - 密码哈希：`crypto.scrypt(password, salt, 64)`，`salt` 每次设置/修改时用 `crypto.randomBytes(16)` 生成；落盘只存 `salt` 与 `hash`（hex）。
  - 校验：重新派生后 `crypto.timingSafeEqual` 比较，防时序侧信道。
  - 会话内状态 `unlocked`（主进程内存，布尔），标记本次会话是否已解锁。

- 新增 IPC：

  | 通道 | 入参 | 说明 |
  | --- | --- | --- |
  | `app:setPassword` | `{ old?, next }` | `next` 为空 → **移除密码**；`old` 非空 → **修改**需先校验旧密码；`old` 空且已有密码 → 拒绝；无旧密码直接设。成功返回 `{ ok:true }`，failed 返回 `{ ok:false, reason }`。 |
  | `app:unlock` | `password` | 校验密码；成功置 `unlocked=true` 并返回 `true`。 |
  | `app:getSecurity` | — | 返回 `{ hasPwd, lockEnabled, lockMinutes, unlocked }`（**不下发任何密码哈希**）。 |
  | `app:setLockConfig` | `{ enabled, minutes }` | 保存超时锁定开关与分钟数；校验 `minutes` 为 1–120 整数。 |
  | `app:lockNow` | — | 主动锁定（可选，暂不接 UI）。 |

- 超时侦测（桌面版优先）：

  - 主进程启动定时器，每 15s 轮询 `powerMonitor.getSystemIdleTime()`；`lockEnabled && hasPwd && unlocked && idle >= lockMinutes*60` 时触发锁定：`unlocked=false`，向主窗口 `webContents.send('app:locked')`。

### 2.2 启动遮罩（SEC-01）

- 密码未设：直接进入主界面，不走遮罩。
- 密码已设：
  - `app.whenReady` → `loadConfig()`，并在 `createWindow()` 后由渲染端查询 `app:getSecurity`。
  - `index.html` 内置全屏遮罩 `<div id="lock-screen">`（`z-index` 最高，覆盖全屏）。启动后若 `hasPwd && !unlocked`：遮罩显示、**主视图隐藏**（`body.locked` → 隐藏 Ribbon 与视图容器，避免内容瞬时闪现泄露）。
  - 输入密码 → `app:unlock` → 成功：移除 `body.locked`、隐藏遮罩、初始化主视图。

### 2.3 超时遮罩（SEC-02）

- 收到主进程 `app:locked`（桌面）或渲染端自身空闲定时器（网页版）后，弹出**同一遮罩组件** `#lock-screen`（fixed 覆盖全屏）。
- 解锁成功即移除遮罩，不重建、不刷新主视图，恢复原界面。
- 网页版空闲侦测：渲染端监听 `mousemove / keydown / scroll / pointerdown`，重置计时器；`lockEnabled && hasPwd && unlocked && 静默 ≥ lockMinutes` 触发锁定。

### 2.4 设置面板（「隐私与安全 → 应用密码」）

在 `js/settings/settings-panels.js` 的「隐私与安全」分类下新增「应用密码」区块：

- 未设密码：密码输入框 ×2（密码 + 确认）+「设置密码」按钮。
- 已设密码：显示「当前：已启用」；「修改密码」（旧+新+确认）、「移除密码」按钮。
- 超时锁定：开关 `toggle`（`lockEnabled`）+ 分钟数输入框（默认 10，1–120）。
- 进入分类时 `app:getSecurity` 回填控件状态；操作成功即提示并刷新状态。

### 2.5 Preload（preload.js）

- 暴露 `setPassword` / `unlock` / `getSecurity` / `setLockConfig` / `onLocked(cb)`。

### 2.6 样式（css/app.css）

- `#lock-screen`：`position:fixed; inset:0; z-index:99999` 背景品牌色半透明/毛玻璃，居中密码框、标题、错误提示。
- `body.locked`：隐藏主视图容器（`visibility:hidden` 或 `display:none`），防内容泄露。

## 三、边界

- 密码仅本地存储（scrypt 哈希），**不加密笔记内容**；笔记明文仍直接落盘，本功能只做「进入/恢复」门槛。
- 忘记密码无法找回（本地无明文），提供「移除密码需旧密码」流程；无旧密码时只能重置（后续可加一次性重置）。
- 显式不引入 bcrypt 原生依赖，避免 electron 打包/跨平台编译问题。
- `powerMonitor` 仅桌面（main 进程）可用；网页版退化到渲染事件计时。

## 四、验证

- `node --check` 语法检查；`npm test` 回归不破坏既有 240 用例。
- 真机确认：设置页开启后重启需输密码；超时遮罩弹出与解锁恢复；修改/移除密码符合预期。
- 验证 `crypto.timingSafeEqual` 分支与边界（空密码、错误旧密码、非法 minutes）不抛错。
