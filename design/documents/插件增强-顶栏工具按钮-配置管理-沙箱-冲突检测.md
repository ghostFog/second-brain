# 插件系统增强：顶栏工具按钮 + 配置管理 + 沙箱 + 冲突检测

## Context（为什么做）

当前插件系统只支持左侧 Ribbon 竖向按钮，缺顶部横向工具按钮；插件管理页是扁平列表，无配置能力；插件回调出错会直接冒泡到宿主；插件之间可能存在 actionKey / 扩展点冲突但无检测。

本次为第二脑（Electron 自研应用，非第三方）的插件系统做四方面增强，让插件机制更接近 Obsidian 的成熟形态。

**用户已确认的决策：**
1. 插件「独立设置」用 **manifest 声明 schema**（通用机制，非写死）
2. 插件冲突检测用 **全套方案**，设置页插件行标红「冲突」徽章
3. 顶栏工具按钮放 **窗口控制按钮（min/max/close）左侧**

## 需求清单

| # | 需求 | 说明 |
|---|------|------|
| 1 | 顶栏工具按钮 | 新增顶部横向按钮扩展点（window-controls 左侧），manifest `toolbar` 字段 |
| 2 | Minimal Theme | ribbon → toolbar，只在顶栏显示，左侧不显示 |
| 3 | Code Highlight | 无 ribbon 无 toolbar，保持只有 commands + contextMenus |
| 4 | 插件配置管理 | 设置页插件管理改二级展开：基本设置 + 插件独立设置（schema 渲染） |
| 5 | 插件沙箱保险 | 单个插件报错不影响整个应用 |
| 6 | 插件冲突检测 | 动作监控：actionKey / 扩展点冲突检测 + 设置页标红 |

## manifest schema 设计

### toolbar（顶栏按钮）
```json
"toolbar": { "icon": "palette", "title": "Minimal 主题切换", "actionKey": "cycle-theme" }
```
- 与 ribbon 互斥，两者都声明时优先 toolbar
- actionKey 在 materializePlugin 中替换为 onClick（复用现有 ribbon 逻辑）
- 点按钮在 window-controls 左侧），manifest `toolbar`

### settings（插件独立设置 schema）
```json
"settings": [
  { "key": "defaultTheme", "label": "默认配色方案", "type": "select",
    "sub": "应用启动时自动套用的主题配色",
    "options": ["停用","纸白","亚麻","冷灰","墨绿"], "default": "停用" },
  { "key": "lineno", "label": "显示行号", "type": "toggle", "default": true },
  { "key": "brightness", "label": "亮度", "type": "range", "min": 0, "max": 100, "step": 1 }
]
```
- `type`: `toggle`(checkbox) / `select`(dropdown) / `range`(slider)
- 存储：`localStorage['plugin:<id>:<key>']`（不并入全局 `note-app:settings`）
- 插件读：`PluginAPI.getSetting(id,key)`；写：`PluginAPI.setSetting(id,key,val)`（同时派发 `plugin-setting-changed` CustomEvent）

## 要改的文件

### 1. `index.html` — 顶栏容器 + 脚本标签
- 在 `.titlebar-actions` 与 `.window-controls` 之间插入：
  ```html
  <div id="plugin-toolbar" class="flex items-center gap-1 px-1" style="-webkit-app-region: no-drag;"></div>
  ```
  （容器自身 `no-drag`，否则整条 header 是 drag，按钮点不了）
- 在 `app-plugins.js` 之后、`app-settings.js` 之前插入：`<script src="js/app-toolbar.js?v=1"></script>`

### 2. `js/app-toolbar.js`（新增）— ToolbarManager
- `globalThis.ToolbarManager`，暴露 `registerPluginButton({id,icon,title,onClick,pluginId})` / `removePluginButton(id)` / `render()` / `init()`
- `render()` 重建 `#plugin-toolbar`：每个按钮 `<button data-plugin-toolbar>`，点击 handler 内 `try/catch → PluginAPI._markError`
- 不持久化顺序（顶栏空间宝贵，按安装顺序追加）；按钮存在性 = installed + enabled
- 末尾调全局 `refreshIcons()`

### 3. `js/app-plugins.js` — 核心骨架（改动最大）
- 新增全局监控表：`pluginActionOwner`（key→owner）、`globalThis.pluginConflictMap`、`pluginErrorMap`
- 新增辅助：`claimActionKey(key,id)`、`recordConflict(key,b)`、`markPluginError(id,err)`
- 改 `PluginAPI.register`：每个 action 包 try/catch 错误边界 + `claimActionKey` 冲突登记
- 改 `materializePlugin`：新增 `toolbar` 展开（复刻 ribbon）+ 对 toolbar/ribbon/commands/contextMenus 做扩展点占用登记，写回 `result.__conflicts`
- 改 `pluginManager.install`：优先 toolbar 分支（`ToolbarManager.registerPluginButton`）→ ribbon → 否则 refresh
- 改 `pluginManager.uninstall`：同时 `ToolbarManager.removePluginButton`
- 新增 `PluginAPI.getSetting/setSetting/_markError`
- 新增 `isPluginEnabled(id)`（localStorage `plugin:<id>:enabled` ≠ 'false'），并过滤 `getCommands/getContextMenus/getRibbonItems`
- `initPluginSystem` 末尾调 `ToolbarManager.render()` 兜底

### 4. `js/app-settings.js` — 插件管理二级展开
- 重写 `cat === '插件管理'` 分支（L76-84）：
  - 一级：图标+名称+状态徽章（异常红色/冲突红色/启用）+ 展开箭头
  - 二级（默认隐藏）：「基本设置」（启用开关+描述+卸载按钮）+「插件独立设置」（`renderSchemaForm`）
- 新增 `renderSchemaForm(p)`：按 `p.settings` 逐项生成 toggle/select/range 控件，初始值从 `localStorage['plugin:<id>:<key>']` 取（缺省用 schema default）
- 新增 `bindPluginDetail(root)`：展开箭头 toggle、设置控件 change/input → `PluginAPI.setSetting`、启用开关 → `isPluginEnabled`、卸载复用现有 uninstall
- `switchSettings(cat)` 中 `cat==='插件管理'` 渲染后调 `bindPluginPanel(content)`

### 5. `plugins/minimal-theme/manifest.json`
- `ribbon` → `toolbar`（icon palette / title / actionKey cycle-theme）
- 新增 `settings`：defaultTheme(select) + hoverToolbar(toggle)

### 6. `plugins/code-highlight/manifest.json`
- 保持不变（无 ribbon/toolbar）
- 新增 `settings`：theme(select) + lineno(toggle) + copybtn(toggle)

## 沙箱隔离（错误边界落点）

| 层 | 位置 | 说明 |
|----|------|------|
| 核心 | `PluginAPI.register` | 每个 action 包 try/catch，一处 wrap 全部生效 |
| 兜底 | app-toolbar.js 点击 handler | try/catch → `_markError` |
| 兜底 | app-ribbon.js / 命令面板 / 右键 | action 执行包 try/catch |
| 已覆盖 | activate 钩子、main.js 加载、styles.css 加载 | 已有 try/catch |
| 状态 | `PluginAPI._markError` → `pluginErrorMap` | 设置页读「异常」徽章 |

## 冲突检测

- 数据结构：`pluginActionOwner`（key→首个插件）、`pluginConflictMap`
- 登记时机：
  1. `PluginAPI.register`：同名 actionKey 冲突
  2. `materializePlugin`：toolbar/ribbon/commands/contextMenus 扩展点占用冲突（key 如 `tool:icon|title`、`cmd:label`）
- 检测：`claimActionKey` 遇已占用且非自身 → `recordConflict` → `console.warn` + 写 `pluginConflictMap`
- 展示：materialize 写 `result.__conflicts`，设置页一级行红色「冲突」徽章 + title 显示详情

## 实现顺序（每步可独立验证）

1. `index.html`：插件 toolbar 容器 + app-toolbar.js 标签
2. `js/app-toolbar.js`：新建 ToolbarManager
3. `js/app-plugins.js`：监控表 + register wrap + materialize toolbar + install/uninstall + getSetting/setSetting + isPluginEnabled 过滤
4. `plugins/minimal-theme/manifest.json`：ribbon→toolbar + settings
5. `plugins/code-highlight/manifest.json`：加 settings

## 验证方式

- `node --check` 校验所有改动 JS 语法（minimal-theme/main.js、code-highlight/main.js、app-plugins.js、app-toolbar.js、app-settings.js）
- 项目根 `npm start` 启动 Electron，验证：
  1. 顶栏 window-controls 左侧出现 Minimal palette 按钮，悬停显示 title，点击循环主题
  2. 左侧 Ribbon 不再有 Minimal 按钮；Code Highlight 无任何按钮（命令/右键照常）
  3. 设置→插件管理：插件行可展开二级，「插件独立设置」按 schema 渲染表单，改值刷新后保留
  4. DevTools 注入 `PluginAPI.register('x',{ 'cycle-theme':()=>{} })` → 控制台冲突警告 + 设置页红色「冲突」徽章
  5. 注入抛错 action → 控制台 warn + 设置页「异常」徽章，宿主不崩
  6. 启用开关关闭插件 → 其顶栏/命令/右键消失
- 用 Chrome DevTools Protocol WebSocket（remote-debugging-port 9222）监听 Console，确认零异常
